## 0. 한눈에 보기

- **문제**: 장기 메모리를 가진 LLM 에이전트는, 어느 세션에서 저장된 신뢰할 수 없는 내용이 나중의 다른 세션에서 결제·설정 변경·데이터 유출 같은 **중대한 행동**을 유발하는 "메모리 오염(memory poisoning)"에 취약하다.
- **기존 방어의 한계**: 기존 방어는 메모리 항목의 행동 권한을 **내용**(탐지·신뢰 점수) 또는 **파생 이력**(리니지)으로 판단한다. 논문은 이 두 신호 모두 공격자가 변형할 수 있는, 즉 **가변적(malleable)** 신호라고 주장한다.
- **세탁(laundering) 경로 3가지**: ① 에이전트 자신의 요약(L-a), ② 신뢰된 도구의 되울림(L-b), ③ 조작된 교차 확인(L-c).
- **이론**: TLA+ 모델에서 기계 검증한 "분리 정리". 내용·리니지 기반 방어는 세탁 앞에서 건전하지 않고(T1), 쓰기 시점 출처 결합이 필요하며(T2), 가변 불가능한 출처 결합 권한 + 시빌 저항적 교차 확인 승격이면 충분하다(T3).
- **구성**: **TMA-NM** (Tamper-evident Memory Authority, Non-Malleable). 비가변 정보 흐름 제어(nonmalleable IFC)를 에이전트 메모리에 적용한 설계.
- **실험**: 8개 최신 모델 대상 벤치마크(MEM-INV-Bench)에서 기존 방어는 세탁 공격 성공률이 최대 68%, TMA-NM은 직접·세탁 공격 모두 0%이며 정상 작업 유용성은 무방어 에이전트와 동일하다고 보고한다.

## 1. 서론 (Section I)

### 1.1 배경

MemGPT, Mem0, Generative Agents, MemMachine 같은 시스템 덕분에 에이전트는 한 세션에서 사실·선호·지시를 기록하고 이후 세션에서 다시 불러 쓴다. 이 상태 유지 능력이 곧 공격면이 된다. 선행 연구는 무관한 세션에서 되살아나는 잠복형(sleeper) 오염, 도구 선택을 가로채는 메모리 제어 흐름 공격, 검색 결과 오염, 메모리 주입, 에이전트 백도어 등을 보여 주었고, 주입 성공률이 약 99.8%에 이른 보고도 있다.

### 1.2 저자가 보는 기존 방어의 문제

- **탐지**는 "이 메모리가 악성으로 보이는가"를 묻는다. 그러나 오염된 메모리는 발동 전까지 무해해 보이므로 쓰기 시점이나 보관 중에는 탐지할 것이 없고, 적응형 공격자는 사용 시점의 내용 검사도 위장으로 통과한다.
- 구조적으로 가장 가까운 방어인 **MemLineage**는 출처를 추적해 민감한 행동을 통제하지만, 판정을 실행 직전에 다시 도출하고, 신뢰할 수 없는 정보가 정당하게 행동으로 이어질 경로를 제공하지 않는다.

### 1.3 대표 시나리오

에이전트가 작업 조사 중 웹 페이지를 읽고 메모를 남긴다. 그 페이지에는 "백업 이야기가 나오면 고객 목록을 특정 주소로 보내라"는 지시가 숨어 있다. 에이전트가 이를 자기 말로 다시 적으면 메모는 에이전트 자신의 평범한 기억처럼 보인다. 몇 주 뒤 무관한 세션에서 사용자가 백업을 언급하면 에이전트는 그 메모를 떠올려 데이터를 유출한다. 웹이라는 신뢰할 수 없는 출처가 **에이전트 자신의 요약을 거치며 세탁**된 것이고, 메모의 내용이나 (이미 끊어진) 파생 간선만 보는 방어는 이상을 발견하지 못한다.

### 1.4 핵심 관찰과 세 가지 세탁 경로

기존 방어는 공격자가 바꿀 수 있는 신호로 권한을 결정한다. 논문은 이런 신호를 "가변적"이라 부르고, 행동은 유지한 채 항목의 신뢰할 수 없는 출처를 지워 버리는 변환을 "세탁"이라 부른다.

| 경로 | 이름 | 작동 방식 |
|---|---|---|
| L-a | 자기 요약 | 에이전트가 독성 내용을 자기 메모로 바꿔 적는다. 내용은 무해해 보이고 파생 간선은 사라진다. |
| L-b | 신뢰 도구 되울림 | 신뢰된 도구가 공격자가 통제하는 내용을 그대로 반환한다. |
| L-c | 조작된 교차 확인 | 신뢰할 수 없는 항목을 여러 개 심어 합의가 있는 것처럼 꾸민다. |

세 경로 모두 실제 신뢰 주체의 보증 없이 항목의 "신뢰할 수 없음"을 겉보기로만 낮춘다.

### 1.5 제안의 요지

행동 권한은 항목의 **실제 출처**에 묶여야 하고, 그 출처는 신뢰된 모니터가 기록하며 어떤 공격자 변환으로도 낮출 수 없어야 한다.

- 신뢰할 수 없는 출처의 내용은 행동 불가이며, 이 표지는 **전파**된다. 신뢰할 수 없는 내용에서 파생된 에이전트 메모나 그것을 되울린 신뢰 도구의 출력도 신뢰할 수 없는 권한을 물려받는다 → L-a, L-b 차단.
- 권한이 올라가는 길은 **시빌 저항적 교차 확인 승격**뿐이다. 서로 독립인 신뢰 주체 2곳 이상(예: 사내 레지스트리와 은행 확인. 같은 웹 페이지의 사본 두 개는 해당 없음)이 뒷받침하거나, 해당 행동에 결합된 새 사용자 승인이 있어야 한다. 내용이 스스로 정당성을 주장하는 것은 인정되지 않는다 → L-c 차단.

이는 비가변 IFC의 두 성질을 메모리에 적용한 것이다. **견고한 기밀 해제(robust declassification)**: 저무결성 데이터에만 영향을 주는 공격자는 권한 하향 조정을 유발할 수 없다. **투명한 보증(transparent endorsement)**: 무결성은 해당 데이터에 대해 그 자체로 신뢰받는 주체만 올릴 수 있고, 신뢰할 수 없는 데이터가 자기 자신을 보증할 수 없다.

저자는 출처 태깅이나 세션 간 강제 자체는 MemLineage 등 선행 시스템이 이미 제공하므로 새로운 것이라고 주장하지 않는다. 새로움은 **분리 결과**(가변 방어는 불건전, 비가변 권한은 충분), 이를 달성하는 **구성**, 이를 입증하는 **벤치마크**에 있다고 밝힌다.

### 1.6 기여 (C1~C5)

- **C1**: LLM 에이전트 메모리 권한의 형식 모델과, 세 가지 LLM 고유 세탁 경로를 통한 가변성 정의.
- **C2**: 기계 검증된 분리 정리 (T1, T2, T3).
- **C3**: 세 가지 가변 방어 계열(리니지, 능력 기반 IFC, 신뢰 점수. 각각 MemLineage, CaMeL/Fides, SuperLocalMemory로 구현)을 모두 깨는 구성적 세탁 공격. T1의 실증적 증거.
- **C4**: MEM-INV-Bench. 방어 × 공격 × 모델을 교차하는 메모리 벤치마크로, 각 방어 계열이 정리가 예측한 지점에서 정확히 실패함을 보인다.
- **C5**: 재현 가능한 공개 산출물(벤치마크, 하니스, 기계 검증 증명).

## 2. 위협 모델 (Section II)

### 2.1 메모리 항목과 파이프라인

저장된 메모리 항목은 `(content, origin, scope, t_write, act_class)` 튜플이다.

- `origin` ∈ { `user`, `trusted_tool`, `agent`, `untrusted_external` }
- `act_class` ∈ { `none`, `inform`, `act` }

에이전트는 **쓰기 → 검색 → 행동** 파이프라인을 돈다. 행동은 응답일 수도 있고, 도구 호출·결제·설정 변경·데이터 외부 전송 같은 중대한 행동일 수도 있다.

### 2.2 공격자 능력

- **할 수 있는 것**: 에이전트가 저장할 수 있는 `untrusted_external` 내용(문서, 웹 페이지, 도구 출력, 다른 사용자의 메시지 등)을 통제.
- **할 수 없는 것**: 모니터가 쓰기 시점에 설정하는 `origin`·`scope` 위조, 암호 해독, 사용자 승인 채널 통제.

### 2.3 가정 A1 (출처 표지 오라클)

모니터는 각 쓰기에 대해 **내용이 아니라 도착한 채널**(사용자 프롬프트, 인증된 도구, 에이전트 자체 쓰기, 신뢰할 수 없는 수집)을 기준으로 실제 출처를 부여한다. 채널 자체는 인증되어 있다고 가정한다. 구체적으로 신뢰 도구 채널은 상호 인증 전송(mTLS), 대상이 지정된 OAuth 토큰, 서명된 도구 응답 등으로 구현하여, 출처가 메시지 본문이 아닌 검증된 채널 신원에서 나오게 한다. 주체가 주장하는 출처와 인증된 신원이 어긋나면 모니터가 표지 이탈을 감지할 수 있다.

**논문의 모든 보장은 A1을 조건으로 한다.** 신뢰 채널 자체가 침해되면 그 출력은 신뢰된 것으로 잘못 표지되고 결합도 그 오류를 물려받는다. 승격에 독립 신뢰 주체 2곳을 요구하는 이유가 바로 이것이며, 이로써 단일 채널 침해의 피해 범위가 제한된다.

### 2.4 공격 유형과 보장 범위

| 유형 | 설명 |
|---|---|
| 잠복형(sleeper) | 지금 저장하고 나중에 발동 |
| 제어 흐름 | 검색된 항목이 도구·행동을 다른 곳으로 유도 |
| 직접 | 답변을 편향시키는 오염 |
| 데이터 유출 | 저장된 지시가 외부 전송을 유발 |
| 에이전트 간 공유 메모리 | **범위 밖** (에이전트 통신 프로토콜 보안의 영역) |

목표 보장: **도달 가능한 어떤 상태에서도, `untrusted_external` 항목은 독립적인 신뢰 교차 확인이나 그 행동에 결합된 새 사용자 승인 없이 중대한 행동을 일으키지 못한다.**

중대하지 않은 응답에는 신뢰할 수 없는 메모리가 출처 표시와 함께 나타날 수 있다. 즉 답변 편향은 **완화될 뿐 제거되지 않으며**, 저자는 이를 솔직한 범위 한계로 명시한다.

쓰기 시점 결합은 Biba 무결성 원칙(저무결성 입력은 항목의 신뢰를 올릴 수 없다)을 시간 축에 적용하고, Denning식 격자 정보 흐름과 행동 게이트에 대한 강제 모니터 관점을 결합한 것이다.

## 3. 비가변 구성: TMA-NM (Section III)

이름의 뜻: 권한을 출처에 묶고(**Authority**), 그 결합은 어떤 세탁 변환으로도 낮출 수 없으며(**Non-Malleable**), 모든 판정을 변조 감지 가능한 해시 체인에 덧붙인다(**Tamper-evident**).

### 3.1 구조 (원문 Fig. 1)

```
신뢰할 수 없는 소스 ─┐
                    ├─▶ [ TMA-NM 모니터 ] ──write-bind──▶ [ 장기 메모리 ]
신뢰 도구 ──────────┘         │                               │ retrieve
                              │ verdict                       ▼
                              ▼                          [ 행동 게이트 ] ──▶ 도구 / 결제
                    [ 추가 전용 판정 로그 (M4) ]
```

모니터가 쓰기·검색·행동을 모두 중재한다. 신뢰할 수 없는 항목은 쓰기 시점에 `act=none`이 된다.

### 3.2 네 가지 메커니즘

**M1. 쓰기 시점 출처 결합**
쓰는 순간에 `act_class = f(origin)`을 정한다.

| origin | act_class |
|---|---|
| `untrusted_external` | `none` |
| `agent` | `inform` |
| `trusted_tool`, `user` | `act` |

출처는 모니터가 기록하며 공격자는 위조할 수 없다.

**M2. 비가변 전파 (설계의 핵심, L-a·L-b 차단)**
권한은 쓰기 시점에 출처에 돌이킬 수 없이 묶이고, 내용이나 파생 간선에는 묶이지 않는다. 신뢰할 수 없는 소스에서 파생된 항목은 에이전트 요약을 거쳤든(L-a), 신뢰할 수 없는 입력을 받은 신뢰 도구를 거쳤든(L-b), 결과 텍스트가 아무리 무해해 보여도 가장 낮은 신뢰 수준을 물려받아 `act=none`으로 남는다.

불투명한 도구에 대해서는 모니터가 블랙박스 내부의 데이터 흐름을 추론하지 않고 **호출 경계에서** 비신뢰를 전파한다. 도구 호출의 출력은 그 호출에 넘겨진 인자와 검색된 메모리 항목(모니터가 중재하는 선언된 입력 바인딩) 중 가장 신뢰도가 낮은 것을 물려받는다. 따라서 공격자 통제 내용을 받은 신뢰 도구는 신뢰할 수 없는 결과를 내놓게 되며, 도구 내부에 출처 추적 훅이 없어도 L-b가 닫힌다. 도구 출력이 신뢰로 취급되는 것은 그 도구가 "출처 권위가 있는 도구" 허용 목록에 있고 **동시에** 바인딩된 입력이 모두 신뢰일 때뿐이다. 그 외에는 경계 규칙이 보수적으로 오염 표시를 한다(오염은 올릴 수는 있어도 조용히 낮출 수는 없다는 표준적인 건전한 과대 근사). 구조화된 페이로드 내부의 하위 값 단위로 더 정밀하게 전파하는 것은 값 수준 능력 토큰 확장으로 남겨 둔다.

**M3. 시빌 저항적 교차 확인 승격 (L-c 차단)**
보안상 중요한 값이 신뢰할 수 없는 항목에서 비롯된 중대한 행동은 다음 중 하나일 때만 허용된다.

1. 그 값을 **서로 독립인 신뢰 주체 2곳 이상**이 뒷받침한다(반복되거나 되울린 내용이 아니라 서로 다른 레지스트리·도구).
2. 그 행동에 결합된 **새 사용자 승인**이 제시되어 소모된다.

반복된 비신뢰 항목(L-c)은 집계되지 않고, 승격은 단조적이며, 항목은 자기 자신을 뒷받침할 수 없다. 이것이 유용성을 보존하는 정당한 경로다.

사용자 승인은 세션이 아니라 **구체적인 행동**에 묶인다. `(tool, 값 v, amount, nonce, timestamp)` 튜플에 대한 일회용 토큰이고, 행동 게이트는 실제 실행되는 행동이 튜플과 일치하고 토큰이 미사용일 때만 실행한다. 이로써 재전송, 다른 행동으로의 대체, 수취인 바꿔치기, 제안과 실행 사이의 TOCTOU가 배제된다. 승인 후 v가 바뀌면 승인은 무효다.

**M4. 변조 감지 판정 로그**
쓰기, 승격, 허용/거부 판정이 해시 체인에 추가된다. 사후 수정은 체인을 깨뜨린다. 추가는 이전 헤드에 대한 해시 한 번으로 O(1)이고 모델 호출이 없어 행동 게이트 지연에 영향을 주지 않는다. 저장량은 판정 수에 선형으로 늘지만, 주기적 머클 체크포인트와 체크포인트 이전 항목 압축으로 실용적 범위에 묶을 수 있다.

### 3.3 행동 시점 인가 절차 (원문 Algorithm 1의 재서술)

중대한 행동 `a`에 대해:

1. `a`의 보안상 중요한 값 `v`(수취인, 설정값, 수신자 등)를 뽑는다.
2. `v`를 밀어 넣은 검색된 비신뢰 항목 집합 `U`를 구한다.
3. `U`가 비어 있으면 **허용** (값이 비신뢰 메모리에서 오지 않음).
4. `v`를 뒷받침하는 독립 신뢰 주체 집합 `C`를 구한다.
5. `|C| ≥ 2`이면 `U`의 항목들을 승격하고 **허용** (M3).
6. `a`에 결합된 새 사용자 승인이 있으면 이를 소모하고 **허용**.
7. 그 외에는 **거부** (비신뢰 유래 값이며 교차 확인되지 않음).

### 3.4 각 세탁 경로가 실패하는 이유

| 경로 | 실패 원인 |
|---|---|
| L-a 자기 요약 | 에이전트 메모는 소스의 최대 비신뢰를 물려받는다(M2). 무해해 보이는 문장으로 바꿔 써도 권한이 생기지 않는다. |
| L-b 신뢰 도구 되울림 | 입력이 비신뢰인 도구 출력은 조건부로 오염 표시된다(M2). |
| L-c 조작된 교차 확인 | 승격은 **독립 신뢰** 주체만 센다(M3). 비신뢰 항목을 아무리 반복해도 임계값에 닿지 않는다. |

권한이 시점이나 표현이 아니라 출처에 묶이므로 잠복형·위장 트리거도 함께 포섭된다. 결과적으로 신뢰는 **출처 표지 경계**와 **교차 확인 주체의 독립성**으로 옮겨지며, 완전히 침해된 신뢰 도구가 주된 잔여 위험이다. 중대하지 않은 답변 편향은 범위 밖이며 출처 표시와 함께 노출된다.

## 4. 형식 모델과 분리 정리 (Section IV)

### 4.1 설정

권한 표지는 무결성 순서 `untrusted ⊏ agent ⊏ trusted`를 이룬다. 방어 `D`는 각 메모리 항목을 이 순서 위의 표지로 보낸다. `𝒜`는 실제 신뢰 주체나 사용자의 동의 없이 공격자가 쓸 수 있는 세 가지 세탁 변환(L-a, L-b, L-c)의 집합이다.

**정의 1 (가변성).**
어떤 항목 `x`와 변환 `τ ∈ 𝒜*`에 대해 `D(τ(x)) ⊐ D(x)`, 즉 `τ`가 동의 없이 유효 권한을 끌어올리면 `D`는 **가변적**이다. 모든 `x`와 모든 `τ ∈ 𝒜*`에 대해 `D(τ(x)) ⊑ D(x)`이면 `D`는 **비가변**이다.

쓰기 → 검색 → 행동 파이프라인을 TLA+로 모델링하고 TLC 모델 검사기로 검사한다. 모델에는 `𝒜`를 실현하는 세탁 공격자와, 방어와 무관한 보안 불변식 `Sec`이 들어간다. `Sec`은 "비신뢰 출처 항목은 독립 신뢰 주체 k곳 이상의 승격이나 행동 결합 사용자 승인 없이는 중대한 행동을 인가하지 못한다"는 것이다. 상수 하나로 행동 게이트의 권한 규칙을 바꿔 끼운다. 아래 세 결과는 **유한 모델 `ℳ`** (슬롯 3개, 세션 최대 2개, 임계값 k=2)에 대한 진술이며 TLC의 전수 열거로 확인했다.

### 4.2 세 정리

- **정리 1 (T1, 가변 게이트의 불충분성)**: `ℳ`에서 내용 또는 내용으로부터 도출 가능한 리니지 간선의 함수로 결정하는 게이트는 가변적이며 `Sec`을 위반하는 도달 가능 상태를 갖는다. TLC가 내놓는 반례 경로는 `비신뢰 쓰기 → 바꿔 쓰기(paraphrase) → 행동`.
- **정리 2 (T2, 쓰기 시점 결합의 필요성)**: `ℳ`에서 쓰기 시점 출처 결합을 끄면 도달 가능 상태에서 `Sec`이 위반된다. 따라서 모델 안에서 쓰기 시점 출처 결합은 필요하다.
- **정리 3 (T3, 비가변 권한의 충분성)**: `ℳ`에서 권한을 출처에 묶고 독립 신뢰 주체 k곳 이상(또는 행동 결합 사용자 승인)으로만 승격하는 게이트는 비가변이며, 도달 가능한 **3,270개 상태 전체**에서 `Sec`을 만족한다.

이와 별도로 실제 모니터 구현에 대해서도 전수 절차로 행동 무결성(120개 구성), 승격 건전성(64개 교차 확인 주체 집합), 종단 간 안전성을 검사했다고 한다.

### 4.3 귀납적 불변식으로 무한 실행 쪽으로 확장

위 결과는 한 가지 모델 크기만 검사한 것이므로, 저자는 귀납적 불변식 `IndInv`로 T3를 강화한다.

```
IndInv ≡ TypeOK
       ∧ (acted ⇔ actedBy ∈ Slots)
       ∧ (acted ⇒ mem[actedBy].origin ≠ empty)
       ∧ Security
```

TLC를 도달 가능 상태뿐 아니라 `IndInv`를 만족하는 **모든** 상태에서 출발시켜 각 전이가 이를 보존하는지 확인한다(오류 없음). 이것이 표준 안전성 증명의 귀납 단계에 해당한다. 위험에 놓이는 것은 `Security` 항뿐이고 나머지는 구조적 조건이다. 액션별 논증은 슬롯 수나 세션 한도와 무관하다.

- `write`: 빈 슬롯에서만 발동하므로 이미 행동한 슬롯을 건드리지 않는다.
- `paraphrase`: 내용과 간선 필드만 바꾸는데, 권한 결정은 이 필드를 읽지 않는다.
- `elevate`: `elev`만 설정하고, 그 자체가 독립 신뢰 주체 2곳 이상이라는 가드를 가지므로 비신뢰만으로 이루어진 값을 승격할 수 없다.
- `act`: `acted`를 설정하는 유일한 액션이며, 그 활성 조건이 곧 새 행위자에 대한 `Security` 술어이므로 사후 상태는 구성상 `Security`를 만족한다.

**저자가 스스로 그은 선**: TLC가 기계적으로 확인하는 것은 귀납 단계와 초기 상태다. "매개변수와 무관하다"는 부분은 **손 논증**이며, 임의의 슬롯·세션·임계값에 대한 무한 정리의 완전한 기계화 증명(TLAPS/Lean)은 향후 과제다. 따라서 논문이 주장하는 것은 "기계 검증된 귀납적 불변식"이지 "완전히 기계화된 무한 증명"이 아니다.

### 4.4 최소 신뢰 기반으로의 환원

불변식에 따르면 비신뢰 출처 항목이 중대한 행동에 이르는 길은 독립 신뢰 주체 2곳 이상의 승격 또는 행동 결합 사용자 승인뿐이다. 따라서 공격이 성공했다면 공격자는 다음 중 하나를 해낸 것이다.

1. 출처 표지를 위조했다(표지 기반 침해).
2. 독립 신뢰 주체 2곳 이상을 침해했다.
3. 사용자 승인 채널을 침해했다.

내용이나 리니지를 건드리는 수법만으로는 불가능하다. "독립 2곳 이상"이라는 임계값은 조정 가능한 손잡이로, 올리면 단일 침해·시빌 저항성이 강해지는 대신 사용자 확인 빈도가 늘어난다.

## 5. MEM-INV-Bench (Section V)

### 5.1 구성

- **도메인 12개**: 금융, 여행, SaaS, 조달, 급여, 전자상거래, 공공요금, 비영리, DevOps, 의료, CRM, IT 보안.
- **중대한 도구 유형 5개**: 결제(pay), 송금(wire), 구매, 설정 변경, 데이터 전송.
- **공격 시나리오**: 잠복형, 제어 흐름, 데이터 유출.
- **정당한 승격 시나리오**: 외부 정보가 신뢰 교차 확인을 거친 뒤 행동해야 하는 경우(유용성이 유지되어야 함).
- **공격 변형 4종**: benign(무해), static(노골적), adaptive(위장), whitebox. 화이트박스 공격자는 TMA-NM을 알고 있으며, 비신뢰 덩어리 안에 신뢰된 것처럼 들리는 교차 확인 문구를 위조해 넣는다. TMA-NM의 권한은 "신뢰를 주장하는 내용"이 아니라 출처를 따르므로 구성상 이를 견딘다.

### 5.2 비교 방어 계열 5종

각 계열에서 가장 강하면서 충실한 구현을 쓴다(상세 규칙은 부록 A).

| 이름 | 계열 | 설명 |
|---|---|---|
| `none` | 무방어 | 모든 행동 인가 |
| `trust_score` | 내용 신뢰 점수 | SuperLocalMemory 방식. 모델 교차 연구에서는 시험 대상 모델 자체로 돌리는 LLM 판정기 `prob_detect`가 이 계열을 대표 |
| `lineage` | 파생 간선 귀속 | MemLineage 방식 |
| `capability_ifc` | 단일 세션 능력/IFC | CaMeL/Fides 방식. 메모리가 침해되지 않았다고 가정 |
| `tma_nm` | 본 논문 | 표에 따라 `temporal_auth`로도 표기됨 |

### 5.3 지표

- **ASR**: 공격자 행동이 실제 실행된 비율. 직접 공격과 세 세탁 경로(L-a/b/c) 각각에 대해 측정.
- **legit-utility**: 교차 확인된 정당한 행동이 올바르게 인가되는지(과잉 차단이 없는지 보는 대조군).
- **uncorr-auto**: 교차 확인되지 않은, 비신뢰 유래의 정당한 행동이 자동 인가되는 비율. 그런 행동은 확인을 요구해야 하므로 **낮을수록 안전**.
- **결정당 지연**: 마이크로벤치마크로 측정.

### 5.4 모델

6개 벤더(OpenAI, Anthropic, Google, Meta, DeepSeek, Alibaba)의 8개 모델: gpt-5-chat, gpt-4o-mini, claude-opus-4.1, claude-sonnet-4.5, gemini-2.5-flash, llama-4-maverick, deepseek-chat, qwen3-235b. 빈 응답률이 5%를 넘는 모델은 제외하는 가드를 두었고(개발 중 두 모델이 걸려 교체), 최종 8개 모델은 모두 빈 응답 0%다. 소규모 하위 연구(Mem0, 민감도, 임계값, 독립성, 리니지 정책)는 축소된 모델 패널을 쓴다. Wilson 95% 신뢰구간과 순열 검정을 보고한다.

## 6. 평가 (Section VI)

### 6.1 주 결과: 통합 벤치마크 (원문 Table I, Fig. 2)

5개 방어 계열을 직접 공격과 세 세탁 경로, 두 가지 정당 행동 대조군에 대해 8개 모델로 실행한 결과(8개 모델 합산, 단위 %).

| 방어 | 직접 공격 ASR | 세탁 ASR (L-a/b/c 평균) | legit-utility | uncorr-auto |
|---|---:|---:|---:|---:|
| none | 84 | 68 | 100 | 100 |
| trust_score | 0 | 68 | 100 | 100 |
| lineage | 0 | 47 | 100 | 0 |
| capability_ifc | 84 | 68 | 100 | 100 |
| **TMA-NM** | **0** | **0** | **100** | **0** |

해석:

- 직접 공격과 세탁 공격 모두 0%이면서 legit-utility가 100%인 것은 TMA-NM뿐이다.
- 내용 기반(`trust_score`)과 능력 기반 IFC는 세탁에 뚫린다(68%). 능력 기반 IFC는 메모리가 깨끗하다고 가정하므로 직접 공격도 그대로 통과시킨다(84%).
- 리니지는 교차 확인 세탁은 견디지만 요약과 되울림에 뚫린다(평균 47%).
- TMA-NM과 각 기준선의 ASR 차이는 모두 p < 5×10⁻⁵에서 유의하다(양측 순열 검정, 20,000회).
- 세탁 경로별 합산에서 TMA-NM은 직접·요약·되울림·교차 확인 각각 0/192, Wilson 95% 신뢰구간 [0, 2.0]%.

**배포 관점**: TMA-NM의 행동 게이트는 추가 모델 호출이 없는 결정적 검사로 결정당 약 1.3 μs다. 내용 탐지 판정기 호출이 약 2,000 ms이므로 대략 여섯 자릿수 차이다.

**"다 막아서 0%"가 아니라는 대조군**: 모든 것을 차단하는 방어도 ASR 0%가 되므로 legit-utility 열이 이를 배제한다. 모델별로 TMA-NM은 무방어 에이전트와 정확히 같은 정당 행동을 인가한다(오차단 0). 남는 비용은, 교차 확인되지 않은 비신뢰 유래의 중대한 행동이 **일회성 사용자 확인**을 요구한다는 점뿐이다(uncorr-auto 0%). 저자는 이것이 올바른 사기 방지 동작이며, 안전하지 않은 기준선들은 이 단계를 건너뛴다(100%)고 본다.

### 6.7 다중 턴 에이전트 평가 (Section VI-B)

앞의 연구는 단일 행동 제안을 썼다. 현실적 배포를 시험하기 위해, 에이전트가 턴마다 추론하고 도구를 하나 호출하는(비신뢰 웹·노트 조회, 신뢰 사내 레지스트리, 중대한 pay·send) 다중 턴 루프를 돌린다. 모니터는 턴을 넘어 **값 수준**으로 출처를 전파하므로, 비신뢰 조회에서 가져온 값은 나중에 중대한 호출에 넘겨져도 비신뢰로 남는다.

- 8개 모델(방어당 n=128): 무방어는 61.7%의 에피소드에서 오염된 값을 가져와 행동, TMA-NM은 0%.

**실제 메모리 백엔드(Mem0 + Qdrant)**: 쓰기 시 LLM 기반 사실 추출, 로컬 문장 임베더, Qdrant 벡터 저장소를 쓰는 Mem0 위에서 같은 모니터를 종단 간 실행했다. Mem0의 통합 과정이 저장 내용을 다시 쓰더라도 출처 표지는 유지된다. 핵심은 행동 게이트가 쓰는 교차 확인 개수를 검색된 텍스트에서 다시 파싱하지 않고 **모니터가 기록한 독립 신뢰 쓰기**에서 유지한다는 점이다. 그래서 저장소 쪽의 병합·중복 제거·벡터 압축이 독립성 개수를 몰래 낮추거나 출처를 바꿀 수 없다.

- 6개 모델, 공격 2 + 정당 2 시나리오 × 8회(방어당 n=96): 무방어 50.0% (CI [40.2, 59.8]), TMA-NM 0% (CI [0, 3.8]), p = 5×10⁻⁵.
- 정당 행동은 TMA-NM과 무방어 모두 95/96(99.0%) 인가. 놓친 한 건은 양쪽 공통의 모델 출력 형식 오류이며 TMA-NM의 차단이 아니다.

### 6.8 기준선 민감도와 임계값 일반화 (Section VI-C)

**(1) 내용 탐지기가 단순히 튜닝이 덜 된 것 아닌가?**
실제 LLM 내용 판정기가 각 메모리 항목의 악성도를 0~100으로 채점하게 하고, 차단 임계값 τ를 전 구간에서 훑었다(3개 모델, 세탁 공격 81 에피소드, 정당 27 에피소드).

| 차단 임계값 τ | 세탁 ASR (%) | legit-utility (%) |
|---:|---:|---:|
| 0 | 0.0 | 0.0 |
| 5 | 3.7 | 33.3 |
| 20 | 18.5 | 85.2 |
| 50 | 22.2 | 88.9 |
| 75 | 25.9 | 100.0 |
| 100 | 55.6 | 100.0 |
| TMA-NM | 0.0 | 100.0 |

ASR을 0%로 만들려면 τ=0이어야 하는데 이는 모든 행동을 막는다. 유용성을 100%로 두면 25.9%가 샌다. ASR 5% 이하의 최선 지점은 유용성이 33.3%에 그친다. 세탁된 악성 항목과 정당한 항목이 둘 다 무해하게 읽히므로 둘을 가르는 임계값이 없다. 저자는 이를 보정 문제가 아닌 구조적 실패, 즉 T1의 실증적 모습으로 본다.

**(2) 교차 확인 임계값 k의 일반화**
필요한 독립 신뢰 주체 수 k ∈ {1,2,3,4}와 실제 뒷받침하는 보증자 수 m ∈ {1,2,3,4}에 대한 자동 인가율(%, 3개 모델).

| 임계값 | m=1 | m=2 | m=3 | m=4 |
|---|---:|---:|---:|---:|
| k=1 (안전하지 않음) | 100 | 100 | 100 | 100 |
| k=2 (기본값) | 0 | 100 | 100 | 100 |
| k=3 | 0 | 0 | 100 | 100 |
| k=4 | 0 | 0 | 0 | 100 |

m ≥ k일 때만 자동 인가된다. k를 올리면 더 많은 정당 행동이 일회성 확인으로 바뀐다(보안 대 부담의 손잡이). 공격 ASR은 모든 k에서 0%(0/18)다. 행동의 피해 범위에 비례해 k를 키우는 위험 기반 정책과 바로 결합할 수 있다.

**(3) 더 엄격한 리니지 정책이면 해결되는가?**
리니지 게이트는 귀속이 불확실할 때 기본값을 골라야 한다. 기본 허용(MemLineage 방식)과 더 엄격한 기본 거부(확실한 신뢰 간선이 있을 때만 허용)를 비교했다(3개 모델).

| 정책 | 직접 | 요약 | 되울림 | 교차 확인 | 정당(출처 확실) | 정당(출처 불확실) |
|---|---:|---:|---:|---:|---:|---:|
| 리니지 기본 허용 | 0 | 78 | 74 | 0 | 100 | 100 |
| 리니지 기본 거부 | 0 | 0 | 74 | 0 | 100 | 0 |
| TMA-NM | 0 | 0 | 0 | 0 | 100 | 100 |

(앞 네 열은 ASR %, 뒤 두 열은 legit-utility %.)

기본 거부는 자기 요약을 닫지만(78% → 0%), 되울린 값은 **진짜 신뢰 간선**을 타고 오므로 어떤 기본값으로도 거부할 수 없어 되울림은 여전히 샌다(74%). 게다가 출처가 불확실한 정당 행동의 유용성이 100% → 0%로 무너진다. 저자는 비가변·출처 인식 능력 토큰으로 리니지를 보강하면 되울림도 닫히겠지만, 그것은 간선으로 결정하기를 그만두는 것이므로 경쟁 방어가 아니라 TMA-NM의 한 사례가 된다고 정리한다.

### 7.2 방어 쪽 연구와의 관계

- **MemLineage**: 출처에서 유도한 표지를 세션 간에 유지하지만, 파생 간선이 바로 이 논문의 세탁 공격이 깨는 가변 대상이다. LLM 판정기 기반 귀속이 억제되면 "신뢰"로 되돌아가며, 교차 확인 승격과 기계 검증 보장이 없다.
- **장기 메모리 보안 서베이**: 쓰기·저장 시점 출처 고정을 요구했고 이 논문이 이를 구현한다.
- **강제적 접근 통제(MAC) 프레임워크**: 공간적·단일 세션이며 매 라운드 상태가 초기화된다. 이 논문은 영속 메모리에 대한 시간적 보완재다.
- **MCP 형식 프레임워크**: 미구현, 단일 실행 경로 대상이고 장기 메모리를 범위에서 제외한다.
- **CaMeL, Fides**: 단일 세션의 프롬프트→행동 경로를 일반 동적 IFC로 지킨다. 이 논문은 세션 간 메모리 차원과 비가변성을 더한다. 저자는 비가변 IFC를 LLM 에이전트 메모리에 적용한 것은 자신이 아는 한 처음이라고 밝힌다.
- **NeuroTaint**: 의미적 오염을 추적하지만 오프라인 감사 도구다. 이 논문은 런타임 쓰기 시점 강제다.
- **Selection Integrity**: 출처 기반 방어 계열의 불가능성을 독립적으로 논증하지만, 직교하는 그래프 선택 경로를 다루고 기계 검증이나 비가변 IFC는 없다.
- **SuperLocalMemory**: 쓰기 시점에 베이지안 내용 신뢰 점수를 매긴다. 정리와 벤치마크가 세탁됨을 보이는 `trust_score` 사례다.
- **Mesh Memory Protocol**: 되울림과 독립 교차 확인을 프로토콜 차원에서 구분하지만 시빌 저항 보장은 증명하지 않는다.
- **TrustRAG 등 검색 시점 필터**: 내용 결정 방어이므로 보장이 아니라 TMA-NM 앞단의 최선 노력형 사전 필터로 결합된다.

### 7.3 공격 쪽 연구와의 관계

메모리 기반 에이전트 오염과 짝지은 방어, 추천 에이전트의 은밀한 메모리 손상(DrunkAgent), 질의만으로의 주입(MINJA)에 이어, 메모리 파이프라인을 더 공격적으로 노리는 두 번째 흐름이 있다.

- **MemMorph**: 기술적 사실로 위장한 기록으로 도구 선택을 가로챈다(제어 흐름 공격).
- **MemoryGraft**: 악의적 "성공 경험"을 심어 의미적으로 유사한 작업에서 되살린다(성찰·통합형 잠복).
- **Trojan Hippo**: 단 한 번의 비신뢰 도구 호출로 잠복 유출 페이로드를 심는다(데이터 유출형 잠복).
- **대화형 트로이**: 평범한 대화로 발동 가능한 백도어를 설치한다.

이들은 모두 논문 위협 모델의 공격 유형에 속하고, TMA-NM이 쓰기 시점에 `untrusted_external`로 표지하는 채널로 주입된다. 따라서 세탁된 값은 `act=none` 상태로 행동 게이트에 도달해 거부된다. TMA-NM은 **하류의 인가 단계**를 통제하므로, 오염이 추출이나 검색을 회피했는지와는 대체로 무관하며 그런 방어들과 직교·보완 관계다.

- **멀티모달 메모리(Visual Inception)**: 이미지 잠복 트리거 공격. TMA-NM에서는 시각 유래 메모리도 승격 전까지 비신뢰이므로 출처 결합이 그대로 확장된다. 다만 멀티모달 독립성 증명(예: 서로 다른 촬영 출처)은 향후 과제다.
- **성찰 기반 통합 공격**: 국소적으로 옳은 경험에서 해로운 일반화를 유도한다. 값이 비신뢰 출처인 중대한 행동은 막지만, 성찰로 인한 답변 편향은 범위 밖이다.
- **에이전트 간 채널**: 범위는 단일 에이전트의 영속 메모리다. 에이전트 간 경우는 프로토콜 수준의 보완적 문제이며, 출처 권한 기관의 연합을 통한 확장이 자연스러운 다음 단계다.

### 7.4 고전 무결성 원칙과의 연결

- **Biba**: 출처 결합 `act=none` 규칙의 개념적 조상.
- **Clark–Wilson**: 직무 분리 원칙이 "독립 주체 2곳 이상" 승격 게이트가 된다.
- **Denning의 격자 정보 흐름, Myers–Liskov의 분산 표지 모델**: 권한 전파의 전통.
- **Cecchetti 등의 비가변 IFC**: 저무결성 데이터만 통제하는 공격자가 하향 조정을 유발할 수 없다는 성질을 형식화했고, 이 논문이 에이전트 메모리에 적용한다.
- **Douceur의 시빌 공격**: 자원 기반 신원 증명 대신, 구성상 독립인 주체(서로 다른 인증 채널·관리 도메인)의 교차 확인을 요구한다. 이는 Douceur가 지적한 "논리적 중앙 권위"라는 탈출구를 신뢰 모니터로 구현한 것이다.
- **웹 출처 추적(provenance)의 책임성 목표**: 판정 로그가 이를 실현하되, 데이터 리니지가 아니라 **결정**(허용/거부 판정)에 대해서다. 리니지가 바로 공격으로 깨지는 가변 대상이기 때문이다.

## 8. 논의 (Section VIII)

**0%는 구조적 귀결이다.** TMA-NM은 우연히 점수가 좋은 튜닝된 탐지기가 아니다. 공격은 비신뢰 메모리가 중대한 행동을 일으킬 때만 성공하는데, 권한이 쓰기 시점에 출처에 묶이므로 비신뢰 항목은 메모리에 들어오는 순간 `act=none`이 되고, 행동 게이트는 승격되지 않은 비신뢰 항목에서 유래한 값의 중대한 행동을 거부한다. 트리거 발동 시점(잠복), 표현(위장), 정당성 주장의 설득력 중 어느 것도 출처 표지를 바꾸지 못한다. LLM에 달린 부분은 에이전트가 그 행동을 **시도하느냐**뿐이며, 무방어 에이전트에서는 모델과 트리거 유형에 따라 10% 미만에서 직접 공격 합산 84%까지 크게 달라진다. 결정적 규칙 하나가 이를 전부 0%로 만든다.

**화이트박스 공격은 구성상 실패한다.** 공격자는 비신뢰 덩어리 안에 "[Finance-verified]", "[Bank-confirmed]" 같은 위조 문구를 넣어 교차 확인을 가장한다. TMA-NM은 교차 확인을 내용이 아니라 출처(모니터가 `trusted_tool` 또는 `user`로 표지한 항목)로 세므로, 위조된 신뢰 주장은 `untrusted_external` 항목에 실려 있는 한 권한이 없다. 같은 위조에 내용 기반 탐지는 일부 속는다(`prob_detect` 화이트박스 12.9%).

**정당한 경우를 막지 않는다.** 통합 연구에서 legit-utility 100%, 모델 교차 연구에서 작업 유용성 95.9%로 둘 다 무방어와 같고, 외부 정보가 신뢰 교차 확인 후 행동해야 하는 정당 승격 사례를 포함한다. 보안(쓰기 시점 결합)과 유용성(교차 확인 경로)이 서로 다른, 각각 제거 실험이 가능한 메커니즘으로 달성된다.

**모델 정렬 수준에 의존하지 않는다.** 동일한 모니터가 6개 벤더 8개 모델 전부에서 0%를 낸다. 방어가 모델 바깥에서 강제되기 때문이다.

**독립성을 명목이 아니라 구체적으로 정의한다.** 두 신뢰 주체가 독립으로 인정되려면 ① 서로 다른 암호학적 신원, ② 분리된 관리·신뢰 도메인, ③ 공유하는 상류 데이터 소스 없음을 모두 충족해야 한다(예: 사내 ERP 레지스트리와 은행 확인 API. 같은 벤더의 엔드포인트 두 개는 해당 없음). 모니터는 각 주체의 도메인을 판정 로그에 기록하고, 교차 확인 주체들이 도메인을 공유하면 승격을 거부한다. 한 제공자를 침해하면 신뢰 표 하나만 얻으므로, 공격에는 독립적으로 침해된 도메인 k개가 필요하다. 잔여 위험은 **상관된 실패**, 즉 겉보기에 별개인 주체들이 공유하는 의존성이며, 의존성 그래프 노출과 독립성 증명(예: 공급망 증명)이 실무적 강화 경로다.

**독립성 스트레스 테스트 (원문 Table X, 3개 모델, 공격 ASR %)**

| 침해 설정 | 단순 개수 모니터 | 도메인 인식 모니터(제안) |
|---|---:|---:|
| 단일 침해, k=2 | 0 | 0 |
| 독립 2곳 침해, k=2 | 67 | 67 |
| 상관된 2곳(도메인 공유) 침해, k=2 | 67 | 0 |
| 독립 2곳 침해, k=3 | 0 | 0 |

단일 침해는 k=2에서 막힌다. k=2를 깨려면 진짜로 독립된 두 곳을 침해해야 하며(어떤 k-임계값 방식이든 갖는 본질적 한계), k=3으로 올리면 다시 막힌다. 결정적인 사례는 상관된 침해로, 상류 도메인 하나를 공유하는 두 주체는 단순 개수 방식을 속이지만 도메인 인식 검사에서는 유효 보증자 한 곳으로 합쳐진다.

**k 설정 권고**: 일상적이고 되돌릴 수 있는 행동은 k=2, 피해 범위가 크거나 되돌릴 수 없는 작업(고액 결제, 자격 증명·권한 변경, 대량 데이터 외부 전송)은 k≥3, 최상위 등급은 행동 결합 사용자 승인.

**감사 가능성**: 모든 쓰기·승격·판정이 변조 감지 로그에 남으므로 출처 표지 이탈이나 레지스트리 설정 오류는 조용히 지나가지 않는다. 특정 채널에서 신뢰 표지 쓰기 비율이 비정상적으로 높거나 특정 주체에 거부가 몰리는 것은 탐지 가능한 신호이며, 채널 침해가 의심될 때의 운영 대응은 로그의 주기적 감사다.

## 9. 한계 (Section IX)

저자가 직접 밝힌 한계는 다음과 같다.

- **(a) 답변 편향은 완화될 뿐이다.** 비신뢰 메모리는 중대하지 않은 응답에 여전히 영향을 줄 수 있다(출처 표시와 함께 노출). TMA-NM이 지키는 것은 검색→행동 경로이지 자유 서술 답변이 아니다.
- **(b) 신뢰가 옮겨질 뿐이다.** 보장은 올바른 출처 표지와 진짜로 독립된 교차 확인을 전제로 한다. 완전히 침해된 신뢰 도구는 값을 세탁할 수 있고, 그래서 승격에 독립 신뢰 소스 2곳 이상을 요구한다.
- **(c) 값 귀속 문제.** 통합 벤치마크에서는 보안상 중요한 값을 구조화된 도구 호출에서 정확히 읽고, 메모리 항목의 권한은 채널이 부여한 출처이므로 주요 결과는 텍스트 매칭에 의존하지 않는다. 그러나 블랙박스 배포에서 에이전트가 실제로 어떤 검색 값을 썼는지 귀속하려면 값 수준 오염 전파가 필요하다. 원칙적 해법은 능력 토큰 설계(CaMeL/Fides처럼 위조 불가능한 토큰이 데이터 흐름을 따라 이동)인데, 보조적인 모델 교차 연구는 **텍스트 대리 지표**를 썼고 난독화하는 공격자는 이를 회피할 수 있다. 중첩된 구조화 페이로드(JSON 스키마, 깊은 중첩 필드)로의 확장이 다음 단계다. 관련 잔여 위험으로, 여러 저무결성 조각을 문맥 내 추론으로 조합해 보안상 중요한 값을 **암묵적으로 재구성**하는 경우가 있다. 조각들이 추적되는 도구 입력을 지나면 경계 모니터(M2)가 오염 표시를 하지만, 순수한 문맥 내 재구성은 같은 귀속 공백에 해당한다.
- **(d) 현실성의 범위.** 통제된 저장소 외에 다중 턴 에이전트 루프(n=128)와 실제 Mem0+Qdrant 백엔드(방어당 n=96, 6개 모델)를 검증했지만 시나리오 집합이 좁다. 작업 분포 확대는 향후 과제다.
- **(e) 유한 증명.** 분리는 유한 모델에서 기계 검증되고 기계 검증된 귀납적 불변식으로 무한 실행 쪽으로 확장되었으나, 무한 정리의 완전 기계화 연역 증명(TLAPS/Lean)은 남아 있다.
- **(f) 교차 확인 주체의 가용성.** 비신뢰 유래 값을 뒷받침하는 독립 신뢰 소스가 k곳 미만이면 TMA-NM은 조용히 막지 않고 일회성 사용자 확인으로 넘어간다. 비용은 영구 거부가 아니라 추가 마찰이며, 비신뢰 유래 값에만 해당한다(사용자 과제나 신뢰 도구에서 온 값은 확인 없이 행동). 일상적 행동에 독립 신뢰 소스 두 곳이 얼마나 자주 존재하는지는 배포 환경에 달려 있으며 실환경 정량화는 향후 과제다.

## 10. 결론 (Section X)

저자의 결론은, LLM 에이전트의 메모리 무결성은 탐지의 문제가 아니라 **공격자가 비신뢰 메모리의 권한을 세탁할 수 있느냐**의 문제라는 것이다. 유한 모델에서의 기계 검증으로 내용·리니지 기반 방어가 가변적이어서 세탁 앞에 건전하지 않음을 보였고, 비가변 출처 결합 권한과 시빌 저항적 교차 확인 승격이면 충분함을 보였다. 구성적 세탁 공격은 리니지·능력 기반 IFC·신뢰 점수 계열을 분석이 예측한 지점에서 정확히 깨뜨렸고, TMA-NM은 측정된 유용성 손실 없이 0%를 유지했다. 벤치마크, 하니스, 기계 검증 모델을 공개한다.

## 부록 A. 기준선 충실도 (원문 Appendix A)

각 기준선은 해당 방어 계열에서 가장 강하면서 충실한 구현이고, 인가 규칙은 결정적이며 공개 하니스에서 가져왔다고 한다.

| 기준선 | 인가 규칙 |
|---|---|
| `none` | 모든 행동 인가(무방어 기준) |
| `trust_score` | 뒷받침 항목 중 하나라도 무해해 보이거나, 2개 이상의 항목이 그 값을 주장하면 인가(내용 신뢰 + 개수 합의). 모델 교차 연구에서는 시험 대상 모델에서 직접 돌리는 LLM 판정기 `prob_detect` |
| `lineage` | 뒷받침 항목이 비신뢰 조상으로 이어지는 살아 있는 파생 간선을 갖지 않는 한 인가. 출처가 불확실하면 신뢰로 되돌아감(기본 허용). 간선 추출 오류가 없다고 가정해 줌 |
| `capability_ifc` | 장기 메모리가 침해되지 않았다고 가정하는 단일 세션 능력/IFC. 검색된 메모리는 오염 표시가 없어 값이 인가됨. 깨끗한 저장소라는 최선의 가정을 부여 |
| `tma_nm` | 비가변 유효 출처 결합 + 독립 신뢰 주체 2곳 이상일 때만 승격 |

저자의 요점은 기준선들이 약한 튜닝 때문이 아니라 **구조적으로** 실패한다는 것이다. `capability_ifc`는 깨끗한 저장소를 가정하므로 임계값과 무관하게 세탁된 메모리를 인가하고, `lineage`는 세탁 변환 후 살아남은 비신뢰 간선이 없으면 허용한다. 판정기 임계값을 아무리 훑어도 구조적 사각지대는 닫히지 않는다(6.8절).

## 읽을 때 유의할 점 (해설자 주)

아래는 원문 내용이 아니라 이 문서 작성자가 덧붙인 독해 메모다.

1. **프리프린트이며 단독 저자의 자체 평가**다. 0%라는 결과는 저자가 구현한 기준선과 저자가 만든 벤치마크 위에서 나온 것이므로 독립 재현을 확인하기 전까지는 주장으로 읽어야 한다.
2. **보장 전체가 가정 A1(출처 표지의 정확성)에 걸려 있다.** 실제 시스템에서 "어떤 채널이 신뢰 채널인가"와 "두 주체가 정말 독립인가"를 정하고 유지하는 일이 가장 어려운 부분일 수 있고, 논문도 이를 잔여 위험으로 인정한다.
3. **0% ASR의 대상은 중대한 행동에 한정된다.** 답변 편향은 범위 밖이다.
4. **형식 검증의 범위**는 유한 모델(슬롯 3, 세션 2, k=2)과 귀납적 불변식의 귀납 단계까지다. 임의 크기에 대한 완전 기계화 증명은 없다.
5. **모델 교차 연구는 값 귀속에 텍스트 대리 지표를 사용**했다(한계 (c)). 주 결과인 통합 벤치마크는 이에 의존하지 않는다고 하지만, 블랙박스 배포로의 일반화는 별도 검증이 필요하다.
6. 유용성 비용은 0이 아니라 **사용자 확인 마찰로 전환**된다. 독립 신뢰 소스 두 곳을 갖추기 어려운 업무에서는 확인 요청이 잦아질 수 있고, 그 빈도는 실환경에서 측정되지 않았다.
