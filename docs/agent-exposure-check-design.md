# 설계 문서: 에이전트 노출 점검 (제조사 시스템 기능)

> 상태: 초안 (2026년 11월 11일)
> 전제: 삼성이 Galaxy 기기의 시스템 기능으로 제공한다.
> 이 문서는 공개 자료만으로 작성했다. Personal Data Engine의 내부 인터페이스, Google 호환성 요건,
> 법무 요건은 확인하지 못했으며 10장에 따로 모았다.
>
> 배경과 조사 결과: [스마트폰의 AI 에이전트 보안과 개인정보 노출 점검](mobile-agent-security-and-personal-data-exposure.md)

## 1. 문제

스마트폰의 에이전트는 여러 앱을 넘나들며 사용자를 대신해 작업한다. 사용자는 에이전트에 무엇을
허용했는지 권한 단위로만 알 수 있고, 그 권한 뒤에 어떤 개인정보가 있는지는 알지 못한다.

- 권한 관리자는 "사진 권한이 켜져 있는가"에 답한다. 사용자가 알고 싶은 것은 "내 여권 사진을 이 에이전트가
  볼 수 있는가"다.
- Google이 예고한 Privacy Dashboard 확장은 에이전트가 이미 한 일을 보여주는 사후 기록이다.
- 에이전트는 주입된 명령에 따라 닿을 수 있는 것은 무엇이든 읽고 외부로 보낼 수 있어, 과도한 접근 범위의
  실제 위험이 일반 앱보다 크다.

## 2. 목표와 비목표

**목표**

- 폰에 있는 에이전트와 각 에이전트의 접근 범위를 한곳에서 보여준다.
- 접근 범위 안에 있는 개인정보를 데이터 단위로 보여준다.
- 노출을 줄이는 조치를 그 자리에서 할 수 있게 한다.
- 접근 범위가 넓어지는 변화를 알린다.

**비목표**

- 실행 중 공격(프롬프트 인젝션 등)의 탐지·차단. 별도의 런타임 방어가 맡는다.
- 에이전트가 서버 쪽에서 연결한 클라우드 서비스의 점검. 1차 범위에서 제외하고 화면에 "점검 범위 밖"으로 표시한다.
- 기업 관리 기능. Knox Service Plugin 정책과는 별개의 개인 사용자용 기능이다.

## 3. 원칙

1. **분류는 기기 안에서 끝난다.** 민감 항목의 내용과 색인은 기기를 떠나지 않는다.
2. **색인도 보호 대상이다.** 민감 항목 색인은 공격 표적이 되므로 KEEP과 Knox Vault 안에 둔다.
3. **권한이 아니라 데이터로 말한다.** "사진 접근 허용"이 아니라 "신분증 사진 12장에 접근 가능"으로 표시한다.
4. **적게, 중요한 것만 알린다.** 민감 정보는 어디에나 있다. 우선순위화 없는 나열은 무시된다.
5. **한계를 숨기지 않는다.** "이상 없음"이 실행 중 위험이나 클라우드 연결까지 안전하다는 뜻으로 읽히지 않게 한다.

## 4. 구조

```
┌──────────────────────────────────────────────────────────┐
│ 4. 표시와 조치   보안 및 개인정보 보호 대시보드 / Privacy Alert │
├──────────────────────────────────────────────────────────┤
│ 3. 민감도 분류   Personal Data Engine 확장 + 기기 내 분류 모델  │
├──────────────────────────────────────────────────────────┤
│ 2. 접근 범위 수집  권한 · 접근성 · 알림 · AppFunctions · 자동화  │
├──────────────────────────────────────────────────────────┤
│ 1. 에이전트 식별  역할 · 권한 · SDK 시그니처                    │
└──────────────────────────────────────────────────────────┘
        저장: KEEP + Knox Vault        실행: 시스템 권한 구성 요소
```

### 4.1 에이전트 식별

아래 신호 중 하나 이상에 해당하는 앱을 에이전트 후보로 본다.

| 신호 | 의미 |
|---|---|
| 어시스턴트 역할 보유 | 시스템 어시스턴트로 지정된 앱 |
| `EXECUTE_APP_FUNCTIONS` 권한 보유 | 다른 앱의 기능을 찾고 실행할 수 있는 승인된 에이전트 |
| 접근성 서비스 활성화 | 화면 내용을 읽고 조작할 수 있음 |
| 알림 접근 활성화 | 모든 알림 내용(인증번호 포함)을 읽을 수 있음 |
| 화면 캡처 사용 | 화면에 표시되는 모든 것을 볼 수 있음 |
| 알려진 AI SDK 내장 | 앱 안에서 외부 모델로 데이터를 보낼 가능성 |

접근성 서비스는 장애 보조 앱 등 에이전트가 아닌 앱도 쓴다. 신호만으로 단정하지 않고
"확정 에이전트 / AI 기능이 있는 앱 / 넓은 접근 권한을 가진 앱"으로 구분해 표시한다.

### 4.2 접근 범위 수집

에이전트별로 다음 경로를 모은다.

- **런타임 권한**: 연락처, 사진·동영상(전체/선택한 항목만), 문자, 통화 기록, 캘린더, 위치, 마이크, 카메라, 파일
- **화면 기반 접근**: 접근성, 화면 캡처, 앱별 자동화 허용 설정
- **알림 접근**
- **AppFunctions**: 에이전트가 호출할 수 있는 다른 앱의 기능 목록. 앱이 공개한 기능은 OS가 색인하며
  `AppFunctionManager`로 조회한다.
- **처리 위치**: 기기 내 처리인지 클라우드 처리인지 (Galaxy AI는 설정값, 서드파티는 Play 데이터 보안 섹션과 SDK 정보로 추정)

### 4.3 민감도 분류

Personal Data Engine은 여러 앱과 시스템에서 데이터를 모아 기기 안의 지식 그래프로 만들고 질의한다.
새 스캐너를 만들지 않고 이 그래프를 확장한다.

- 그래프의 데이터 항목에 **민감도 범주**와 **도달 경로**(어느 권한·기능으로 접근 가능한가) 속성을 붙인다.
- "에이전트 X가 도달할 수 있는 민감 항목"은 그래프 질의로 구한다.
- 이미지처럼 그래프에 내용이 없는 항목은 기기 내 분류 모델로 보완한다. 신분증 탐지는 경량 탐지 모델로
  문서 종류를 분류한 뒤 OCR을 붙이는 구조가 일반적이다.

초기 민감도 범주:

| 범주 | 예 | 주된 위치 |
|---|---|---|
| 신분 증명 | 주민등록증, 운전면허증, 여권 사진 | 사진첩, 파일 |
| 금융 | 카드·계좌번호, 통장 사본, 거래 알림 | 사진첩, 메모, 문자, 알림 |
| 인증 정보 | 인증번호, 비밀번호 메모, 복구 코드 | 문자, 알림, 메모 |
| 건강 | 진단서, 처방전, 건강 앱 기록 | 사진첩, 파일, Samsung Health |
| 위치 이력 | 집·직장 추정, 이동 기록 | 위치 기록, 사진 메타데이터 |
| 사적 대화 | 메신저·문자 내용 | 메시지 앱, 알림 |

### 4.4 화면을 읽는 에이전트의 처리

화면 캡처·접근성 기반 에이전트는 화면에 뜨는 것은 무엇이든 볼 수 있어 접근 가능한 데이터를 열거할 수 없다.

- 자동화가 허용된 앱 단위로 "이 앱들의 화면 전체가 노출 범위"로 표시한다.
- 허용된 앱 안에 민감 범주가 많은 앱(금융, 메신저, 건강)이 있으면 그 사실을 강조한다.

## 5. 데이터 모델

```
Agent
  id, 패키지명, 유형(확정 에이전트 | AI 기능 앱 | 넓은 접근 앱)
  식별 신호[], 처리 위치(기기 내 | 클라우드 | 혼합 | 알 수 없음)

AccessPath
  agent_id, 종류(권한 | 접근성 | 알림 | 화면 캡처 | AppFunction | 자동화 허용)
  대상(권한명 | 대상 앱 | 기능 식별자), 범위(전체 | 선택 항목), 허용 시각

SensitiveItemGroup          ← 개별 항목이 아니라 묶음 단위로 표시
  범주, 위치(앱/저장소), 항목 수, 도달 가능한 AccessPath[]

Exposure                    ← 화면에 보이는 한 줄
  agent_id, 범주, 항목 수, 경로 요약, 위험 점수, 권장 조치[]

ChangeEvent
  시각, agent_id, 변화 종류(신규 에이전트 | 권한 확대 | 기능 추가 | 처리 위치 변경)
```

개별 민감 항목의 내용은 저장하지 않는다. 범주, 위치, 개수만 색인하고, 사용자가 항목을 열어볼 때
원본 앱에서 직접 불러온다.

## 6. 위험 점수

상위 몇 건만 알리기 위한 우선순위 계산이다.

```
위험 점수 = 민감도 가중치 × 처리 위치 가중치 × 접근 폭 가중치 × 최근 사용 가중치
```

| 요소 | 높음 | 낮음 |
|---|---|---|
| 민감도 | 신분 증명, 인증 정보, 금융 | 일반 사진, 일정 |
| 처리 위치 | 클라우드, 알 수 없음 | 기기 내 |
| 접근 폭 | 화면 전체·전체 사진 | 선택한 항목만 |
| 최근 사용 | 최근 실제 접근 있음 | 허용만 되어 있고 미사용 |

오래 쓰지 않은 에이전트의 넓은 권한은 점수는 낮아도 "회수 권장"으로 따로 묶어 보여준다.

## 7. 화면 구성

위치: 설정 > 보안 및 개인정보 보호 > 에이전트 노출 점검

1. **요약**: 에이전트 수, 주의가 필요한 노출 건수, 마지막 점검 시각, 점검 범위 밖 항목 안내
2. **에이전트 목록**: 에이전트별 접근 범위 요약과 처리 위치
3. **에이전트 상세**: 접근 경로, 도달 가능한 민감 항목 묶음, 호출 가능한 앱 기능, 최근 활동
4. **데이터 기준 보기**: 범주를 고르면 그 범주에 닿을 수 있는 에이전트를 역으로 보여준다
   ("내 신분증 사진을 볼 수 있는 것은 무엇인가")
5. **변화 기록**: 접근 범위가 넓어진 이력

노출 한 건의 표시 예:

> **○○ 어시스턴트**가 신분증 사진 12장에 접근할 수 있습니다.
> 경로: 사진 및 동영상 전체 접근 · 처리: 클라우드
> [선택한 사진만 허용] [보안 폴더로 이동] [권한 회수]

## 8. 조치

| 조치 | 설명 |
|---|---|
| 권한 회수 | 기존 권한 관리자와 같은 동작 |
| 범위 축소 | 전체 접근을 선택 항목 접근으로 전환 |
| 민감 항목 격리 | 해당 항목을 보안 폴더로 이동해 에이전트의 접근 범위 밖으로 뺀다 |
| 자동화 허용 해제 | 특정 앱에 대한 에이전트 자동화를 끈다 |
| 알림 내용 숨김 | 인증번호 등 민감 알림을 알림 접근 앱에 전달하지 않는다 |
| 미사용 에이전트 정리 | 오래 쓰지 않은 에이전트의 권한을 일괄 회수 |

조치는 항상 사용자가 선택한다. 자동 회수는 하지 않는다.

## 9. 단계별 범위

| 단계 | 내용 | 민감 데이터 읽기 | 산출물 |
|---|---|---|---|
| **1. 권한 기반 지도** | 에이전트 식별, 접근 경로 수집, 에이전트 목록·상세 화면, 권한 회수·범위 축소 | 없음 | 4.1, 4.2, 화면 1~3 |
| **2. 데이터 단위 점검** | 민감도 분류, 노출 표시, 데이터 기준 보기, 위험 점수, 민감 항목 격리 | 있음 (기기 내) | 4.3, 6장, 화면 4 |
| **3. 지속 감시** | 변화 감지와 Privacy Alert 연동, 미사용 에이전트 정리, 알림 내용 숨김 | 있음 (기기 내) | 변화 기록, 화면 5 |

1단계는 민감 데이터를 읽지 않아 위험이 낮고 단독으로도 출시할 수 있다. 차별점은 2단계에서 나온다.
2단계의 초기 범주는 신분 증명, 인증 정보, 금융 세 가지로 좁혀 시작한다.

## 10. 열린 질문

**내부 확인이 필요한 것**

- Personal Data Engine이 색인하는 데이터 범위와, 민감도·도달 경로 속성을 추가할 수 있는 확장 지점
- 사진첩의 기존 이미지 분석 결과(문서·신분증 분류)를 재사용할 수 있는지
- Google 호환성 요건상 권한·개인정보 화면을 변경할 수 있는 범위
- Google이 예고한 Privacy Dashboard의 AI 확장과 겹치는 부분의 조율

**법무 검토가 필요한 것**

- 기기 안에서 고유식별정보·민감정보를 자동 분류할 때 요구되는 고지와 동의 (국내 개인정보보호법, GDPR)
- 이미지 속 신분증 탐지 관련 특허 (유출 방지 목적의 미국 특허가 여럿 있다)

**기술 검증이 필요한 것**

- 서드파티 에이전트의 처리 위치를 얼마나 정확히 추정할 수 있는가
- 접근 기록을 조회하는 시스템 API로 "최근 실제 접근"을 어느 정밀도까지 알 수 있는가
- 분류 모델의 오탐률. 신분증 탐지는 스크린샷처럼 문서와 비슷한 배치에서 오탐이 난다는 보고가 있다
- 색인 유지에 드는 배터리·저장 공간 비용

**제품 결정이 필요한 것**

- 기본 활성화 여부. 2단계는 민감 데이터를 읽으므로 명시적 동의 후 켜는 방식이 안전하다
- 삼성 자체 에이전트(Bixby, Galaxy AI)를 서드파티와 같은 기준으로 표시할지. 같은 기준을 적용해야 신뢰를 얻는다
- 서드파티 에이전트 개발사에 처리 위치·데이터 사용 선언을 요구하는 방안
