## 1. 왜 이 선례를 보는가

검토 중인 아이디어는 사용자가 개인정보에 "차단" 또는 "확인 후 제공" 라벨을 붙이고, 에이전트에 데이터가
넘어가는 시점에 그 라벨대로 집행하는 것이다.

iOS에는 사용자가 **앱 단위로** 표시를 해 두면 시스템이 그 앱의 내용을 다른 곳에 내보이지 않는 기능이
두 가지 있다. 개인 기기에서, 일반 사용자가 직접 설정하는 방식이라는 점에서 우리 아이디어의 사용자 경험에
가장 가까운 선례다.

## 2. 요약

- **잠긴 앱·가린 앱(iOS 18, 2024년)**: 원래 목적은 폰을 건네받은 **다른 사람**으로부터 앱을 가리는 것이다.
  부수적으로 잠긴 앱의 정보가 알림 미리보기, 검색, Siri 제안, 통화 기록에 나오지 않는다.
- **제외 앱(iOS 27.2, 2026년 10월)**: 대상이 **AI 어시스턴트**다. 앱을 목록에 넣으면 Siri, 검색, 제안이
  그 앱을 쓰지 못하고, 화면 인식(onscreen awareness)도 그 앱 안에서 동작하지 않는다.
- 두 기능 모두 **앱 단위**이고, 동작은 **전부 막거나 전부 허용**이다. 데이터 항목 단위 통제와
  제공 시점의 사용자 확인은 없다.
- 두 기능의 관계(잠긴 앱이 Siri AI의 개인 맥락이나 화면 인식에서 자동으로 빠지는지)는 확인하지 못했다.

## 3. 잠긴 앱과 가린 앱 (iOS 18)

### 3.1 동작

| 구분 | 내용 |
|---|---|
| 잠금 | 앱을 열 때 Face ID, Touch ID 또는 암호를 요구한다 |
| 잠긴 앱의 정보 | Apple 문서: "일부 위치에 나타나지 않는다. 예를 들어 알림 미리보기, 검색, Siri 제안, 통화 기록" |
| 가리기 | 잠금에 더해 홈 화면에서 사라지고 앱 보관함 맨 아래의 "가려진 항목" 폴더로 옮겨진다 |
| 설정 방법 | 앱 아이콘을 길게 눌러 선택한다(검색 결과 요약 기준) |
| 기기 간 동기화 | 되지 않는다. 설정한 기기에서만 적용되며 iCloud로 동기화되지 않는다 |

Apple 문서의 목록은 "예를 들어"로 시작한다. 정보가 나오지 않는 위치의 전체 목록은 공개되어 있지 않다.

### 3.2 제약

- **잠글 수 없는 앱**: 계산기, 카메라, 시계, 연락처, 나의 찾기, 지도, 단축어, 설정.
- **가릴 수 없는 앱**: iOS 18 이후에 기본 설치된 앱 전체. 따로 내려받은 앱만 가릴 수 있다.
- **가족 공유**: 13세 미만은 잠그거나 가릴 수 없다. 13~17세는 가능하지만 보호자가 앱의 다운로드 여부와
  사용량을 볼 수 있고 스크린 타임으로 제한할 수 있다.
- 기본 브라우저나 메일 앱으로 지정된 앱은 가릴 수 없다는 보도가 있다(검색 결과 요약 기준).

### 3.3 가려도 드러나는 곳

Apple 문서는 가린 앱이 "iPhone의 다른 곳에서는 여전히 보인다"고 명시한다.

| 위치 | 출처 |
|---|---|
| 설정 > 앱 > 가려진 앱 (인증 필요) | Apple 문서 |
| 설정 > 스크린 타임 | Apple 문서 |
| 설정 > 배터리 > 배터리 성능 상태 및 충전 | Apple 문서 |
| App Store 구입 내역 | Apple 문서 |
| 백그라운드 앱 새로 고침 목록 | 9to5Mac (iOS 18.0 기준) |
| 개인정보 보호 > 사진 (사진 접근 권한을 준 앱인 경우) | 9to5Mac |
| App Store 검색 결과의 "열기" 버튼 | 9to5Mac |
| Safari의 "앱에서 열기" 배너 | 9to5Mac |

- 9to5Mac은 가린 상태가 "완벽하지 않다"고 평가했다. 다만 드러나는 것은 **앱이 설치되어 있다는 사실**이고,
  앱의 내용을 보려면 여전히 인증이 필요하다.
- 9to5Mac의 항목은 2024년 9월 iOS 18.0 기준이며, 이후 버전에서 고쳐졌는지는 확인하지 못했다.

## 4. 제외 앱 (iOS 27.2)

### 4.1 동작

- 위치: 설정 > Siri > 제외 앱(Excluded Apps) > 앱 추가. 여러 앱을 한 번에 고르는 목록이다.
- 앱을 넣으면 그 앱은 **Siri, 검색, 제안에서 쓸 수 없게 된다.**
- **화면 인식은 제외한 앱 안에서 동작하지 않는다.**
- 일부 Siri 기능이 함께 꺼진다. 기사는 메시지 앱을 제외하면 Siri AI가 메시지를 읽거나 답장하지 못한다는
  EFF의 확인을 인용한다.
- 되돌리려면 목록에서 앱을 빼면 된다.

### 4.2 이전 방식과의 차이

- iOS 27.2 이전에는 설정 > Apple Intelligence 및 Siri > 앱에서 앱마다 스위치를 켜고 꺼야 했다.
  "이 앱에서 학습", 검색·위젯의 제안 표시 같은 항목이 따로 있었고, "검색에서 콘텐츠 보기"는 각 앱의
  설정 메뉴에 또 따로 있었다.
- 27.2는 이를 **목록 하나로 합쳤다.** 한 번 넣으면 Siri, 검색, 제안 모두에 적용된다.
- iOS 27.2는 2026년 10월 26일에 나온 것으로 보인다(기사 본문이 아니라 같은 페이지의 다른 기사 제목 기준).
  이 업데이트는 Siri가 쓰는 개인 맥락의 범위(메시지 첨부, 캘린더, 음성 사서함, Safari 기록 등)를 넓힌
  버전이기도 하다(검색 결과 요약 기준).

### 4.3 확인하지 못한 것

- 제외가 **색인, 개인 맥락, 앱 동작 호출(App Intents)** 각각에 적용되는지. 기사는 "Siri, 검색, 제안"이라고만 쓴다.
- 제외한 앱이 제안에는 여전히 나올 수 있다고 쓴 다른 보도가 있어 범위에 대한 설명이 엇갈린다(검색 결과 요약 기준).
- 잠긴 앱·가린 앱과의 관계. 잠근 앱이 제외 앱 목록에 자동으로 들어가는지, 잠긴 앱의 내용이 Siri AI의
  개인 맥락에 쓰이는지는 어느 자료에도 없었다.
- Apple의 공식 문서. 이 기능은 MacRumors 기사로만 확인했고, 같은 내용을 다룬 MacObserver 기사는 열지 못했다.
- 서드파티 AI 앱(ChatGPT 등)에 대한 효과. 이 설정은 Siri에 대한 것이다.

## 5. 우리 아이디어에 주는 시사점

> 이 장은 조사 결과가 아니라 분석이다.

### 5.1 두 기능과 우리 아이디어의 비교

| 항목 | 잠긴·가린 앱 | 제외 앱 | 우리 아이디어 |
|---|---|---|---|
| 막으려는 상대 | 폰을 건네받은 사람 | 시스템 어시스턴트(Siri) | 기기의 모든 에이전트 |
| 통제 단위 | 앱 | 앱 | 데이터 항목 또는 분류 |
| 동작 | 인증 요구, 표시 억제 | 전부 차단 | 차단 또는 확인 후 제공 |
| 무엇이 민감한지 정하는 주체 | 사용자 | 사용자 | 스캔이 제안하고 사용자가 확정 |
| 화면 읽기 경로 | 해당 없음 | 포함 (화면 인식 차단) | 포함해야 함 |
| 에이전트별 구분 | 없음 | 없음 (Siri만) | 에이전트별 설정 |

### 5.2 배울 점

- **통제는 한 곳에 모아야 쓰인다.** Apple은 앱마다 흩어져 있던 스위치를 목록 하나로 합쳤다. 우리 설계도
  에이전트·앱·경로별 설정을 따로 두지 말고 하나의 화면에서 정하게 해야 한다.
- **화면 읽기 경로를 OS가 막을 수 있다는 실례다.** 제외한 앱에서 화면 인식이 동작하지 않는다는 것은,
  OS가 "지금 화면에 있는 앱"을 알고 어시스턴트의 화면 접근을 끊을 수 있다는 뜻이다. 삼성 앱에 대해
  같은 신호를 쓰면 화면 경로의 차단이 가능하다.
- **차단에는 기능 손실이 따른다.** 메시지 앱을 제외하면 Siri가 메시지를 읽지도 답장하지도 못한다.
  앱 단위의 전부-아니면-전무 방식은 사용자가 편의 때문에 끄게 만든다. 이것이 **항목 단위 라벨과 HITL이
  필요한 근거**다. "메시지 전체를 막는다"가 아니라 "인증번호와 계좌번호가 든 메시지만 막는다"가 가능해야 한다.
- **사용자가 직접 고르게 하면 빠뜨린다.** 두 기능 모두 무엇이 민감한지를 사용자가 스스로 판단해야 한다.
  스캔 결과로 "이 앱에 신분증 사진이 12장 있다"를 먼저 보여주는 것이 우리 아이디어가 더하는 부분이다.
- **존재를 감추는 것은 어렵다.** 가린 앱도 설정 화면 여러 곳에서 드러났다. 내용 보호와 존재 은닉을
  구분하고, 후자는 약속하지 않는 편이 안전하다.
- **기기 간 동기화가 없다.** 잠금 상태는 기기마다 따로다. 라벨을 Galaxy 기기 간에 동기화할지, 한다면
  라벨 목록 자체가 민감 정보가 된다는 점을 미리 정해야 한다.
- **시스템 어시스턴트만 대상이다.** 제외 앱은 Siri에 대한 설정이다. 우리 아이디어는 Bixby·Gemini뿐 아니라
  서드파티 에이전트에도 같은 라벨이 적용되어야 차별점이 된다.

### 5.3 이 선례에 없는 것

- 데이터 항목 단위의 통제
- 제공 시점에 사용자에게 묻는 HITL
- 에이전트별로 다른 정책
- 민감 정보의 자동 발견

Purview 선례에도 HITL은 없었다. **두 선례 모두 "차단"만 구현했고, "확인 후 제공"은 선례 없이 설계해야 하는
부분**이다.

## 6. 더 확인해야 할 것

- 제외 앱에 대한 Apple 공식 문서와 정확한 적용 범위(색인, 개인 맥락, App Intents)
- 잠긴 앱의 내용이 Siri AI의 개인 맥락과 화면 인식에서 제외되는지
- 제외 앱이 서드파티 AI 앱의 App Intents 호출에도 영향을 주는지
- 9to5Mac이 지적한 노출 위치가 이후 iOS 버전에서 고쳐졌는지
- Android·One UI에 대응되는 기능(Gemini 연결 앱 설정, Private Space, 보안 폴더)이 에이전트의 화면 접근과
  기능 호출을 어디까지 막는지
