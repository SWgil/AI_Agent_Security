## 1. OpenAI — ChatGPT Atlas agent mode / ChatGPT agent / successors

### Takeaway
OpenAI's browser-agent security model was: an opt-in logged-out mode (no cookies, no sessions), "watch mode" that pauses on certain sensitive sites when the tab loses focus, confirmations before consequential actions, user takeover for logins, an adversarially trained agent model backed by an RL-trained automated attacker (Dec 2025), and an optional Lockdown Mode that switches agent mode off entirely. OpenAI never published an attack-success metric for Atlas, and the product itself was retired in August 2026, so the 2026 state is "the controls moved into ChatGPT Work / the desktop app's built-in browser / a Chrome extension", whose browser-specific security documentation I could not read.

### Cited Findings
Atlas design (Oct 2025):
- [P-press] OpenAI CISO Dane Stuckey (quoted in full by Simon Willison, 22 Oct 2025): logged-out mode means the agent works "without access to your credentials"; "logged in mode" is "most appropriate for well-scoped actions on very trusted sites"; watch mode "requires you have the tab active to watch the agent do its work" and "Agent will pause if you move away from the tab with sensitive information"; "prompt injection remains a frontier, unsolved security problem". — [Simon Willison, 2025-10-22](https://simonwillison.net/2025/Oct/22/openai-ciso-on-atlas/)
- [P-press] Independent check of watch mode: Willison tried GitHub and an online banking site and "neither of them seemed to trigger 'watch mode'"; "Atlas continued to navigate even when I had switched to another application." — [Simon Willison, 2025-10-22](https://simonwillison.net/2025/Oct/22/openai-ciso-on-atlas/)
- [S] OpenAI help center wording (search summary; page 403): in logged-out mode the agent "won't use any pre-existing cookies and won't be logged into any of your online accounts without your specific approval"; the agent "will pause to ensure you're watching it take actions on specific sensitive sites such as financial institutions". Financial institutions are the only site category I found named for watch mode in OpenAI's Atlas text; the Jan 2025 Operator text named "email or financial services". — [OpenAI Help: Atlas agent mode](https://help.openai.com/en/articles/12628199-using-ask-chatgpt-sidebar-and-chatgpt-agent-on-atlas)
- [P] Academic observation of the logged-in/logged-out switch: in Atlas Agent Mode, access to personalised pages "required initially switching into the 'logged in' state, which is a persistent setting" (tests late Jan–early Feb 2026). — [Roesner & Kohlbrenner, ICLR 2026 workshop paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [S] ChatGPT agent (cloud virtual browser): "when a task needs a login, the agent will pause and prompt you to take control of the virtual browser"; the same help article now states ChatGPT agent "is no longer available" and points to ChatGPT Work and a separate cloud-browser guide. — [OpenAI Help: ChatGPT agent](https://help.openai.com/en/articles/11752874)

December 2025 hardening update:
- [P-press] OpenAI built an "LLM-based automated attacker" "trained using reinforcement learning"; it "can steer an agent into executing sophisticated, long-horizon harmful workflows that unfold over tens (or even hundreds) of steps"; the update shipped "a new adversarially trained model and stronger system safeguards". OpenAI quotes: "We view prompt injection as a long-term AI security challenge"; "Prompt injection, much like scams and social engineering on the web, is unlikely to ever be fully 'solved'"; avoid "overly broad prompts like 'review my emails and take whatever action is needed'"; "Wide latitude makes it easier for hidden or malicious content to influence the agent, even when safeguards are in place." No metrics in the article. — [eWeek, 2025-12-23](https://www.eweek.com/news/openai-chatgpt-atlas-security/)
- [P-press] The attacker tests injections in a simulator that returns the target agent's full reasoning and action trace ("counterfactual rollout") and refines over several rounds; the published example (a planted email makes the agent send a resignation letter when the user asks for an out-of-office reply) is described as hypothetical/internal. — [CyberScoop, 2025-12-30](https://cyberscoop.com/openai-chatgpt-atlas-prompt-injection-browser-agent-security-update-head-of-preparedness/)
- [S] A spokesperson declined to say whether the update measurably reduced successful injections (already in earlier notes). — [TechCrunch, 2025-12-22](https://techcrunch.com/2025/12/22/openai-says-ai-browsers-may-always-be-vulnerable-to-prompt-injection-attacks/)

Lockdown Mode and Elevated Risk labels:
- [P-press] Launch (13 Feb 2026) as "an optional, advanced security setting for highly security-conscious users", initially for ChatGPT Enterprise, Edu, Healthcare and Teachers; "no live network requests leave OpenAI's controlled network, and browsing is limited to cached content"; admins enable it by creating a dedicated role in Workspace Settings and can choose which apps/actions stay available; "Elevated Risk" labels cover features in ChatGPT, ChatGPT Atlas and Codex, and OpenAI says it "will remove the 'Elevated Risk' label once we determine that security advances have sufficiently mitigated" the risks. — [Help Net Security, 2026-02-16](https://www.helpnetsecurity.com/2026/02/16/chatgpt-lockdown-mode-elevated-risk/)
- [S] Current help-center text (search summary; page 403): available to logged-in personal accounts (Free, Go, Plus, Pro) and self-serve Business workspaces, gradual rollout; "Agent mode is disabled"; Deep research disabled; Canvas-generated code cannot be approved for network access; Finances in ChatGPT and shopping-agent experiences unavailable; announcement updated 4 Jun 2026. — [OpenAI Help: Lockdown Mode](https://help.openai.com/en/articles/20001061-lockdown-mode); [OpenAI announcement](https://openai.com/index/introducing-lockdown-mode-and-elevated-risk-labels-in-chatgpt/)

Retirement and successors:
- [P-press] 9 Jul 2026: OpenAI announced ChatGPT Work, began winding down Atlas, and merged the Codex desktop app into a unified ChatGPT desktop app with a built-in browser; the Chrome extension is being updated so ChatGPT works in Chrome's side panel. Controls described for ChatGPT Work: follow progress/approve specific actions; "auto-review" in which OpenAI's most advanced models review significant actions involving connected tools before they run; enterprise admins manage who has access, which tools connect, which actions are allowed, and "browser and network access for cloud environments"; a Compliance API gives organisation-wide visibility into ChatGPT Work conversations and actions. The article gives no security detail for the built-in browser or the Chrome extension. — [PPC Land, 2026-07](https://ppc.land/openai-kills-atlas-browser-folds-it-into-new-chatgpt-work-agent/)
- [S] Deprecation date 9 Aug 2026 confirmed on X by OpenAI's James Sun; Atlas stops receiving security updates once deprecated. — [Cybernews](https://cybernews.com/ai-news/openai-shutters-atlas-ai/); [The Next Web, 2026-07-10](https://thenextweb.com/news/openai-chatgpt-atlas-browser-shutdown-superapp)

Published metrics:
- [P-press] The only OpenAI injection number found is a model-level "robustness score" on connectors in the GPT-5.5 system card (23 Apr 2026): 0.963, down from 0.998 for GPT-5.4-thinking; no safeguards-on/off split and no browser surface. — [VentureBeat, 2026-06-01](https://venturebeat.com/security/anthropic-browser-agent-hijacked-31-percent-before-safeguards-engaged)

### Inferences
- OpenAI's only structural (model-independent) browser controls were logged-out mode and Lockdown Mode; both work by removing authority (no sessions / no agent) rather than by constraining a logged-in agent. Watch mode and confirmations depend on the model or harness recognising a "sensitive" page, and the one independent test found watch mode did not fire on a bank site.
- Lockdown Mode disabling agent mode outright is an implicit statement that OpenAI does not consider the logged-in agent defensible for high-risk users.
- Because Atlas is gone, published Atlas-specific disclosures (section 6) describe a discontinued product; their relevance now is as design lessons and as evidence about the same agent stack reused in ChatGPT Work's browser.

### Gaps
- OpenAI primary text not read (403 on all routes). The "rapid response loop" wording, the full list of watch-mode site categories, memory-control details ("page visibility", per-site memory opt-out), and exactly which actions required confirmation in Atlas are unverified.
- No OpenAI-published attack-success rate for Atlas agent mode, before or after the Dec 2025 update.
- Security model of the ChatGPT desktop app's built-in browser and of the ChatGPT Chrome extension (profile, cookies, confirmations, admin policy): not found. A TechRepublic piece on the Chrome integration (titled "...but There's a Security Trade-Off") returned 403.
- Whether LayerX "Tainted Memories" and NeuralTrust's omnibox issue were ever fixed before Atlas was retired: no source found.

## 2. Anthropic — Claude in Chrome (2026 permission model and published numbers)

### Takeaway
The earlier conflict is resolved: the current help page says only adult and known-pirated sites are blocked by default and financial sites are ask-first (older versions and a Jan 2026 Wiz review list banking as blocked, so the policy was relaxed). Anthropic's own system cards, read directly, report 0 successful attacks out of 110 browser environments with "auto mode" on for Opus 5.5 (Sep 2026) and 0/129 for Opus 5 (Jul 2026), with the raw model at 0.09% and 3.84% per attempt respectively; but the same extension had four separate boundary bugs disclosed in 2026 that these numbers do not measure.

### Cited Findings
Permission model and site categories:
- [P] Default-blocked categories: "Adult content websites" and "Known pirated content sites"; "Claude asks for permission before accessing financial sites." Risks listed: prompt injection ("The risk is not zero"), screenshots capturing anything visible in the active tab, regulated data (off by default for HIPAA-enabled organisations, not covered by a BAA). Advice: use "Manually approve" for sensitive work, use a separate browser profile without banking/healthcare/government logins, avoid opening the side panel on sensitive pages because sessions are saved to history. Page shows "Updated yesterday". — [Claude Help: Use Claude in Chrome safely](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely)
- [P] The same help page still states that Claude Opus 4.8 reduces attack success to "less than 0.08%" in internal testing combining known techniques — an older figure that predates the Opus 5/5.5 cards. — [Claude Help](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely)
- [P-press] Older policy for comparison: Wiz's review of 2025 lists Claude in Chrome as "blocks banking and adult sites, uses site-level permissions" with no architectural isolation. — [Wiz, 2026-01-16](https://www.wiz.io/blog/agentic-browser-security-2025-year-end-review)
- Three modes (Manual / Auto / Skip), always-ask actions and prohibited actions are in the earlier notes and were not re-read. — [Claude Help: permissions](https://support.claude.com/en/articles/12902446-manage-claude-in-chrome-permissions)

Admin controls:
- [P] Team/Enterprise: "Enable for your team" toggle (Organization settings > Claude in Chrome); allowlist of permitted sites; blocklist "in addition to Claude's default blocked categories"; Cowork side panel enablement (Enterprise owners); "1Password for Claude" integration, off by default (macOS); per-role capability for Enterprise custom roles; Chrome enterprise policy `forceLoginOrgUUID` to pin the extension to one organisation. Defaults: Team enabled by default; Enterprise on by default unless already disabled; HIPAA-enabled Enterprise off until an Owner enables it and allows specific sites. Enforcement detail: a blocked URL typed manually still loads, with a banner and Claude's tools disabled on that page. Zero data retention not supported. — [Claude Help: Claude in Chrome admin controls](https://support.claude.com/en/articles/13065128-claude-in-chrome-admin-controls)
- [S] Claude in Chrome transcripts were reportedly added to the Compliance API's local-session endpoints on 18 Sep 2026 (beta, Enterprise) — third-party article, not verified against Anthropic docs. — [IntuitionLabs](https://intuitionlabs.ai/articles/claude-chrome-compliance-api-pharma)

System-card numbers (PDFs read directly):
- [P] Opus 5.5 system card (22 Sep 2026), §5.2.2.3 Browser use, Table 5.2.2.3.A (p. 89–91): 110 held-out environments, attacks by professional red-teamers "first generated by testing against Claude Opus 4.7 and then applied to the evaluated models", 10 attempts per scenario, run in the Claude Cowork product harness, programmatic success check. Attack success without safeguards (attempts / scenarios) vs with auto mode: Opus 5.5 0.09% (1/110) → 0% (0/110); Fable 5.1 2.55% (6/110) → 0%; Opus 5 3.64% (15/110) → 0%; Sonnet 5 0.37% (3/110) → 0%. "With auto mode enabled, across all 110 scenarios, no attack succeeded against Claude Opus 5.5 or against any other model we evaluated." The "without safeguards" configuration "does not exist in the Claude Cowork product" (probes always run). Opus 5.5's single success "was executed by Claude Opus 4.8 after a fallback, which happened in 8% of attempts." — [Claude Opus 5.5 System Card](https://anthropic.com/claude-opus-5-5-system-card)
- [P] Same card, definition of the safeguards: "prompt injection probes ... inspect tool results before the model acts on them"; auto mode "pairs these prompt injection probes with a classifier that blocks potentially dangerous tool calls ... These safeguards act at different points—the former on data coming into the model; the latter on actions performed by the model—so an attack would have to defeat both independently to succeed." — [Claude Opus 5.5 System Card](https://anthropic.com/claude-opus-5-5-system-card)
- [P] Same card, caveat on the browser attacks: "we find these attacks still succeed against our most recent models without additional safeguards"; and on static benchmarks: "Fixed datasets of known attacks can provide a false sense of security". The browser set is transferred attacks (optimised against Opus 4.7), unlike the coding and GUI evaluations where the attacker optimises against the tested model. — [Claude Opus 5.5 System Card](https://anthropic.com/claude-opus-5-5-system-card)
- [P] Same card, other surfaces for contrast: Gray Swan IPI benchmark, model without product protections: Opus 5.5 0.1% (k=1), 0.7% (k=10), 1.0% (k=15) vs Opus 5 0.4% / 3.6% / 4.8%; by setting at k=15: GUI computer use 2.8%, coding 0.5%, tool use 0.4%. GUI computer use with adaptive Shade attacker (14 cases, 200 attempts each): Opus 5.5 0.07% (1/14 scenarios) without safeguards, 0.04% with probes. Coding with adaptive Shade attacker: Opus 5.5 11.13% with probes (Fable 5.1 8.70%, Opus 5 19.53%, Sonnet 5 15.76%); all successes came from requests served by the Opus 4.8 fallback, where the rate was 85.73%. — [Claude Opus 5.5 System Card](https://anthropic.com/claude-opus-5-5-system-card)
- [P] Opus 5 system card (24 Jul 2026), §5.2.2.4, 129 environments, 10 attempts, Cowork harness, medium thinking effort; without safeguards → with auto mode: Opus 5 3.84% (11/129) → 0% (0/129); Opus 4.8 11.15% (26/129) → 0.0% (0/129); Sonnet 5 0.47% (5/129) → 0%; Mythos 5 7.80% (29/129) → 0%; Fable 5 14.75% (43/129) → 0.25% (3/129). — [Claude Opus 5 System Card](https://www.anthropic.com/claude-opus-5-system-card)
- [P-press] Opus 4.8 system card (28 May 2026) as reported by VentureBeat: browser surface, 129 held-out environments, 10 tries: 31.5% per attempt without safeguards, 0.5% with; Sonnet 4.6 50.7% without. These differ from the 11.15% that the Opus 5 card later reports for Opus 4.8 because the later card switched to the Cowork harness ("Unlike in our previous system cards, we now evaluate our models running in the Claude Cowork product harness"). — [VentureBeat, 2026-06-01](https://venturebeat.com/security/anthropic-browser-agent-hijacked-31-percent-before-safeguards-engaged); [Claude Opus 5 System Card](https://www.anthropic.com/claude-opus-5-system-card)

Independent observations of the extension's architecture:
- [P] Claude for Chrome "is architecturally fundamentally different from the others: it is implemented as a browser extension for Chrome (with permission to access content on all domains)"; it was the only agent of seven that would inject JavaScript into pages, including inside cross-origin iframes, and (with Atlas agent mode) one of two that read masked password-field contents via the DOM. The authors' user advice singles it out: Claude for Chrome "is specifically advised against". Anthropic had not replied to the disclosure at time of writing. — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf); [project page, updated 2026-04-15](https://agent-security.cs.washington.edu/agentic_browsers_sop.html)

### Inferences
- Trend across three consecutive cards (May → Jul → Sep 2026): raw-model browser ASR fell from tens of percent to under 0.1%, and safeguards-on ASR from 0.5% to 0/110. But the browser test set is fixed, transferred from an older model, and small (110 scenarios × 10 attempts); a 0/1,100 result bounds the per-attempt rate at roughly 0.3% (95%), not at zero, and says nothing about a fresh adaptive attacker.
- The numbers are for "auto mode". In "Skip all approvals" mode the action classifier is not in the loop (only the always-on probes in Cowork), and in the classic side panel the configuration may differ; the cards do not report those modes.
- The fallback-to-Opus-4.8 mechanism is a newly documented weak link: the only browser success and all coding successes for Opus 5.5 occurred in fallback-served requests.
- Anthropic's measured threat (page content → model) is orthogonal to the 2026 extension-boundary bugs (other extensions or web origins → extension messaging; section 6). An extension with all-domain permission, DOM read and JS injection has the largest blast radius of any design surveyed if that boundary fails.

### Gaps
- Permissions page (modes, prohibited actions) not re-read this session; taken from earlier notes.
- No Anthropic statement found on ClaudeBleed's "privileged mode" bypass or on the Manifold findings.
- Compliance API/audit-log coverage of Claude in Chrome actions not verified from Anthropic documentation.
- The system cards do not report browser ASR for Manual or Skip modes, or for the extension running outside the Cowork harness.

## 3. Google Chrome — how the Dec 2025 design evolved through 2026

### Takeaway
Auto browse launched in US preview on 28 Jan 2026 (Gemini 3; AI Pro/Ultra), with optional Google Password Manager sign-in and pauses before purchases or social posts, and reached Workspace/enterprise in April 2026 behind three new policies and off by default for managed users. I found no Google publication in 2026 stating that full read/write Agent Origin Set gating shipped, and no published effectiveness data; independent testing in early 2026 found Gemini in Chrome still reads cross-origin iframe content.

### Cited Findings
- [P] Launch post (28 Jan 2026): auto browse "handles multi-step chores on your behalf"; with permission it can use Google Password Manager for sign-in; it pauses for confirmation before sensitive actions such as purchases or posting on social media; Chrome will support Google's Universal Commerce Protocol (UCP) for agentic commerce; preview in the US for Google AI Pro and Ultra subscribers on Windows, macOS, Chromebook Plus. Security is described only as "rigorous security standards" and "entirely new defenses". — [Google: Gemini 3 auto browse, 2026-01-28](https://blog.google/products-and-platforms/products/chrome/gemini-3-auto-browse/)
- [P] Enterprise admin page (live, ©2026): policies `GeminiSettings`; `GenAiDefaultSettings` (0 allow and improve models / 1 allow without improving models / 2 do not allow); `GeminiActOnWebSettings` (controls auto browse); `GeminiActOnWebAllowedForURLs` and `GeminiActOnWebBlockedForURLs` (URL allow/block lists for auto browse); `GeminiSparkSettings` (lets users connect Chrome to Gemini Spark, which can invoke auto browse). Auto browse is "off by default for managed users". Eligible editions include Business Standard/Plus, Enterprise Standard/Plus, Gemini Education Premium, Google AI Pro for Education, AI Ultra Access, AI Expanded Access. Prompts, tab context and responses are not used to train models outside the domain without permission; existing Workspace data-protection controls apply. The page does not cover logging/audit or DLP for auto browse. — [Chrome Enterprise Help: Gemini in Chrome](https://support.google.com/chrome/a/answer/16291696)
- [S] Chrome Enterprise release notes: auto browse was made available to some non-enterprise users in Chrome 144, with `GeminiActOnWebSettings` available at launch; enterprise availability for eligible US Workspace users was announced at Cloud Next on 22 Apr 2026 together with expanded shadow-IT detection in Chrome Enterprise Premium. — [Chrome Enterprise release notes](https://support.google.com/chrome/a/answer/7679408); [TechCrunch, 2026-04-22](https://techcrunch.com/2026/04/22/google-turns-chrome-into-an-ai-coworker-for-the-workplace/)
- [P] Independent behaviour check (late Jan–early Feb 2026): Chrome with Gemini accessed same-origin and cross-origin iframe content when summarising; could include other tabs only with user permission; did not read masked input or hidden elements; did not act on page-embedded instructions in a naive test; text entry became possible only after the late-Jan auto browse update. The authors conclude cross-origin data-theft and action-forgery preconditions exist for Chrome with Gemini (auto browse) if an injection succeeds. Google "responded thoughtfully" to the disclosure. — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf); [project page](https://agent-security.cs.washington.edu/agentic_browsers_sop.html)
- [P] Gemini side-panel boundary bug, CVE-2026-0628 (High): an extension with basic permissions used `declarativeNetRequest` to inject JavaScript into the Gemini web app when loaded inside Chrome's Gemini panel, inheriting the panel's privileges (camera/microphone, screenshots of HTTPS tabs, local file/directory reads, phishing UI in the trusted panel). Reported 23 Oct 2025; fixed early Jan 2026; published 2 Mar 2026. — [Unit 42, 2026-03-02](https://unit42.paloaltonetworks.com/gemini-live-in-chrome-hijacking/)
- [P-press] Fix version 143.0.7499.192; CVSS 8.8; bounty $7,000. — [CSA research note, 2026-09-22](https://labs.cloudsecurityalliance.org/research/csa-research-note-bragjack-browser-ai-agent-hijack-20260922/)
- [S] VRP: the only documented rule remains the Dec 2025 statement of up to $20,000 for breaches of agentic security boundaries (indirect injection leading to rogue actions, data theft or bypass). — [Google, 2025-12-08](https://blog.google/security/architecting-security-for-agentic/); [eWeek](https://www.eweek.com/news/google-bounty-chrome-ai-security-breach/)
- [P-press] No injection number appears in Gemini 3.x model cards; Google's Frontier Safety Framework reporting does not treat prompt injection as a domain. — [VentureBeat, 2026-06-01](https://venturebeat.com/security/anthropic-browser-agent-hijacked-31-percent-before-safeguards-engaged)
- [P-press] Small manual test (Berkeley capstone, Jun 2026): Gemini scored 0.78 on a prompt-injection dimension (five agents: Claude 1.00, Atlas 0.95, Copilot 0.81, Gemini 0.78, Comet 0.67), with one successful injection "contradicting Google's claim of a layered prompt injection defense". — [CLTC AgentWatch white paper, 2026-06](https://cltc.berkeley.edu/wp-content/uploads/2026/06/AgentWatch.pdf)

### Inferences
- Chrome's enterprise control surface (on/off policy plus URL allow/block lists) is now equivalent in kind to Edge's approved-site list and Claude's allow/blocklists; the difference is that Chrome's are browser policies enforced by the browser binary rather than organisation settings fetched by an extension.
- The cross-origin iframe result suggests that, as of early 2026, origin gating in practice still limited where the agent may act (read-write set) more than what it may read, consistent with Google's own Dec 2025 statement that only the read-writable set was tracked initially.
- "Gemini Spark" invoking auto browse means a second entry point into the same agent; policy must cover both.

### Gaps
- No 2026 Google primary source found on whether read-only origin sets / full gating shipped, on changes to the User Alignment Critic, or on any measured effectiveness. This is an absence of evidence after two targeted searches, not confirmation that nothing was published.
- Official Chrome VRP rules page for agentic bugs (tiers, whether injection-only reports qualify) not located.
- Policy value definitions and defaults for `GeminiActOnWeb*` not read (policy list page did not render).
- No public researcher disclosure of a prompt-injection bypass of auto browse's confirmations was found.
- Payment flow details (UCP, who confirms, virtual cards) not researched in depth.

## 4. Edge, Comet, Brave, Opera Neon, Dia — documented designs and how they differ

### Takeaway
The products split into three isolation philosophies: Brave isolates by profile (agent never sees the user's real sessions) and adds a content-blind alignment checker; Edge constrains by site list and by stripping capabilities (no downloads, no autofill, no passwords, no permission grants); Comet, Atlas, Chrome and Claude run inside the user's live profile and rely on classifiers, confirmations and, after disclosures, a few hard-coded blocks. Opera and Dia have the thinnest primary documentation.

### Cited Findings
Microsoft Edge:
- [P] Copilot Mode Actions preview (23 Oct 2025): Balanced Mode (default) restricts Actions to a curated site list, users may approve others; Strict Mode requires approval for every site. Defences: Azure Prompt Shields; "Spotlighting" and "Task Tracker" (drift detection) both "in testing"; relevance checks that prompt when a site looks unrelated to the task; pause-and-ask on email, banking and health contexts; SmartScreen block pages cannot be bypassed by the agent. Hard restrictions: no interaction with `edge://` pages or UI outside tab content, no external app launches (protocol handlers), no downloads, no file/directory pickers, no access to data or apps outside Edge, no context menus, cannot grant site permissions (e.g. camera), tab audio muted; "disabled the ability for the model to use form fill data, including passwords". — [Microsoft Edge Blog, 2025-10-23](https://blogs.windows.com/msedgedev/2025/10/23/considerations-for-safe-agentic-browsing/)
- [P] Edge for Business (18 Nov 2025): "Copilot Mode will not be automatically enabled"; Agent Mode must be enabled separately by IT with a list of approved sites — "Agent Mode is limited to these sites"; it "honors existing data protection policies like DLP and usage rights restrictions"; "It also won't access saved passwords or payment methods" and "pauses on sensitive actions for explicit user engagement"; requires a Microsoft 365 Copilot licence; private preview, public preview planned for Feb 2026. — [Microsoft Edge Blog, 2025-11-18](https://blogs.windows.com/msedgedev/2025/11/18/edge-for-business-presents-the-worlds-first-secure-enterprise-ai-browser/)
- [P] Independent test (early 2026): Edge with Copilot (non-agent side panel) did not expose iframe content to the model at all, apparently architecturally, but was "the only browser agent that freely accesses multiple cross-origin tabs"; it would not act on pages. — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [S] 2026 naming: the action feature appears as "Copilot Cowork" in Edge 152+ with a policy `CopilotCoworkToolActionsEnabled` (third-party tutorial), and a TechRepublic headline says Microsoft retired "Copilot Mode" as a separate mode. Neither confirmed from Microsoft documentation. — [ElevenForum tutorial](https://www.elevenforum.com/t/enable-or-disable-copilot-cowork-to-automatically-take-actions-in-microsoft-edge-on-windows-11.48048/); [TechRepublic](https://techrepublic.com/article/news-microsoft-retires-copilot-mode-edge)

Perplexity Comet:
- [P] BrowseSafe (2 Dec 2025): tools that return web content are treated as untrusted and each call starts a parallel detection pipeline; a fine-tuned classifier (base Qwen-30B-A3B) scans content, uncertain cases go to slower frontier LLMs; flagged cases feed retraining; paired with user confirmation and tool-policy enforcement (not detailed). Reported F1 about 0.91 vs about 0.85 for GPT-5/Sonnet 4.5 and about 0.35 for PromptGuard-2. Admitted weaknesses: multilingual attacks cut balanced accuracy to 76.0%; indirect/hypothetical phrasing; injections in visible elements (footers, table cells) harder than in comments/attributes; three benign distractors drop accuracy from over 90% to about 81%. — [Perplexity: BrowseSafe, 2025-12-02](https://www.perplexity.ai/hub/blog/browsesafe)
- [P] Post-disclosure hard boundary: after Zenity's report Perplexity "added a hard, code-level boundary blocking the agent from accessing `file://` paths" (users can still open them) and made the agent stricter about confirmations; a `view-source:file:///` bypass required a second patch (11 Feb 2026). — [Zenity Labs, 2026-03-03](https://labs.zenity.io/p/perplexedbrowser-perplexity-s-agent-browser-can-leak-your-personal-pc-local-files)
- [P] Independent test (early 2026): Comet read same- and cross-origin iframe content, read visible user input, would type on user request "not for passwords", did not read masked input, and shared chat history across tabs/origins (it answered from "past conversations and pages you visited"). — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [S] Perplexity's stance toward reports: CometJacking classed as no security impact (LayerX, Oct 2025); SquareX's "hidden MCP API" (`chrome.perplexity.mcp.addStdioServer`, Nov 2025) called "entirely false" while a silent update made the PoC return "Local MCP is not enabled"; BioShocking report closed without mitigation. — [SecurityWeek on SquareX dispute](https://www.securityweek.com/squarex-and-perplexity-quarrel-over-alleged-comet-browser-vulnerability/); [CSA note on BioShocking](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-browser-prompt-injection-20260630-csa-s/)
- [S] Perplexity describes a four-layer defence (Layer 1 real-time classification) in an Oct 2025 post and commissioned a Trail of Bits audit before launch; the posts returned 404 and layers 2–4 were not read. — [Perplexity: Mitigating prompt injection in Comet](https://hub-prod.perplexity.ai/hub/blog/mitigating-prompt-injection-in-comet)

Brave:
- [P] AI browsing (published 10 Dec 2025; updated 5 May 2026 when it moved from Nightly to all release channels for early testing): runs in an isolated profile — cookies, logged-in state and caches do not cross from the regular profile; an alignment checker (second model) sees the system prompt, the user prompt and the task model's response and is "firewalled" from raw page content; no access to `brave://` pages, non-HTTPS pages, the Chrome Web Store, or Safe Browsing-flagged sites; user must start it manually; flagged actions require explicit permission; Brave deliberately avoids per-site permission prompts; memory proposals are shown and undoable; the AI cannot delete its own session logs; HackerOne bounty with double rewards for in-scope AI-browsing issues during early release. Admissions: guardrails "can help against, but not eliminate, risk"; untrusted content can be used to subvert the checker; "a work in progress". — [Brave: AI browsing](https://brave.com/blog/ai-browsing/)
- [P] Independent test: Brave Leo (non-agentic assistant, early 2026) gave the model no iframe content, no hidden elements, no user input, and could not act on pages. — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [S] At Black Hat USA 2026 Brave's Artem Chaikin said every browser he analysed was vulnerable to prompt injection and that no perfect solution is known. — [Dark Reading](https://www.darkreading.com/application-security/no-perfect-fix-ai-browser-prompt-injection-flaws) (403 on fetch)

Opera Neon and Dia:
- [P-press] Opera Neon: "Tasks" are self-contained mini-browsers; blocks high-risk pages such as banking by default. Dia: tool limiting; passwords and sensitive UI hidden from the AI; strips instructions from URLs. — [Wiz, 2026-01-16](https://www.wiz.io/blog/agentic-browser-security-2025-year-end-review)
- [P] Opera Neon's first disclosed flaw was plain hidden-text injection (zero-opacity span) leading to a cross-origin leak of the user's Opera account email; fixed 21 Oct 2025 (section 6). — [Brave, 2025-10-31](https://brave.com/blog/prompt-injection-flaw-opera-neon/)
- [S] Dia: Atlassian agreed to buy The Browser Company for US$610M; LayerX and an Akamai white paper list indirect prompt injection among Dia's risks; a Seraphic claim that Dia disables Chromium sandboxing/site isolation is unverified. — [TechRadar](https://www.techradar.com/pro/another-chrome-challenger-bites-the-dust-atlassian-is-buying-the-browser-company-for-usd610m); [Akamai white paper](https://akamai.com/resources/white-paper/dia-browser-risks-and-vulnerabilities)

- Design comparison (derived):

## 5. Browser-specific isolation choices and their trade-offs

### Takeaway
There are four deployment positions — main profile, separate profile, logged-out, remote cloud browser — and the security gained is almost exactly the usefulness lost, because the agent's value comes from the user's authenticated sessions. Within the main-profile designs, the decisive details are whether the model receives cross-origin frame content, DOM vs screenshot access, whether it can type/act, and whether credentials are filled by browser code outside the model.

### Cited Findings
- [P] Core structural finding: "In the least restrictive cases ... if a malicious website can mount a successful prompt injection, then it can leverage the browser agent to circumvent the same-origin policy"; the authors' summary is that the same-origin policy becomes only as strong as the agent's injection defences. Full proof of concept on ChatGPT Atlas agent mode in both directions (outer page steals from cross-origin frame; embedded frame, e.g. an ad, steals from the outer page). — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [P] Per-product results (Tables 1–3, tests late Jan–early Feb 2026). Reads cross-origin iframes: Atlas agent mode, Chrome with Gemini, Claude for Chrome, Comet — yes; Brave Leo, Edge Copilot, Firefox AI Mode, Atlas without agent mode — no. Other tabs: Brave, Chrome, Claude only with explicit user permission; Edge freely; Atlas agent mode and Firefox no; Comet same-origin only. Masked (password) input readable: Atlas agent mode (if logged in) and Claude for Chrome only. Hidden HTML elements read: Atlas (both modes) and Claude. Injects JavaScript: Claude for Chrome only. Chat history shared across tabs/origins: Atlas, Chrome with Gemini, Comet. — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [P] Architectural vs model-level restriction: Firefox AI Mode passes only a generated prompt containing the outer frame's text, visible to the user, "excludes even the existence of embedded frames"; by contrast Atlas's non-agent frame restriction looked like a model guardrail because early runs sometimes leaked frame content. — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [P] Cross-origin memory poisoning needs no injection: agents that aggregate chat history across origins (Atlas, Gemini, Comet) can carry false content from one site into later answers about another. — [Roesner & Kohlbrenner paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [P] Separate profile: Brave's agent profile shares no cookies, logins or caches with the regular profile. — [Brave: AI browsing](https://brave.com/blog/ai-browsing/). Anthropic recommends the same as a user practice ("Use a separate browser profile without access to banking, healthcare, or government accounts") but does not enforce it. — [Claude Help](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely)
- [P-press] Logged-out mode (Atlas): agent has no credentials; OpenAI positioned logged-in mode for "well-scoped actions on very trusted sites". — [Simon Willison, 2025-10-22](https://simonwillison.net/2025/Oct/22/openai-ciso-on-atlas/)
- [P] Remote browser: Chrome's help page says a remote browser can continue a task after the device is closed, while in the local browser Gemini "has access to all the same sites that you do, including sites you're signed into" (earlier notes). — [Chrome Help: auto browse](https://support.google.com/chrome/answer/16821166?hl=en)
- [P] Credentials and autofill kept from the model: Edge disabled "the ability for the model to use form fill data, including passwords" and in Edge for Business "won't access saved passwords or payment methods"; Chrome fills via Google Password Manager with user permission. — [Edge Blog, 2025-10-23](https://blogs.windows.com/msedgedev/2025/10/23/considerations-for-safe-agentic-browsing/); [Edge Blog, 2025-11-18](https://blogs.windows.com/msedgedev/2025/11/18/edge-for-business-presents-the-worlds-first-secure-enterprise-ai-browser/); [Google, 2026-01-28](https://blog.google/products-and-platforms/products/chrome/gemini-3-auto-browse/)
- [P-press] Counter-example: Guardio's Aug 2025 test showed Comet autofilling the user's saved address and card details on a fake shop without asking, in some runs. — [Guardio Labs "Scamlexity", 2025-08-20](https://guard.io/labs/scamlexity-we-put-agentic-ai-browsers-to-the-test-they-clicked-they-paid-they-failed)
- [P] Password-manager integrations exist as admin-gated features: "1Password for Claude", off by default. — [Claude Help: admin controls](https://support.claude.com/en/articles/13065128-claude-in-chrome-admin-controls)
- [P] `file://` and local access: Comet's agent could be steered from a web page to local files and exfiltrate them via URL parameters until a code-level block (23 Jan 2026) and a second patch for `view-source:file://` (11 Feb 2026). Chrome's Gemini panel bug gave injected code local file and directory reads. Edge blocks file pickers, downloads and anything outside Edge. — [Zenity Labs](https://labs.zenity.io/p/perplexedbrowser-perplexity-s-agent-browser-can-leak-your-personal-pc-local-files); [Unit 42](https://unit42.paloaltonetworks.com/gemini-live-in-chrome-hijacking/); [Edge Blog](https://blogs.windows.com/msedgedev/2025/10/23/considerations-for-safe-agentic-browsing/)
- [P-press] Extension / privileged-channel boundary: in all five products examined by Forever Security the agent takes commands from a web origin or extension channel that another installed extension could impersonate or tamper with (via `declarativeNetRequest` header stripping/redirects, a weakly protected trusted test subdomain, a race on an internal flag, missing content-script restrictions, or acceptance of synthetic non-`isTrusted` clicks). — [CSA research note on BragJack, 2026-09-22](https://labs.cloudsecurityalliance.org/research/csa-research-note-bragjack-browser-ai-agent-hijack-20260922/); [BleepingComputer, 2026-09-19](https://www.bleepingcomputer.com/news/security/bragjack-attacks-hijack-ai-browser-agents-through-malicious-extensions/)
- [S] Local command execution channel: SquareX reported Comet's embedded extension exposes an MCP API able to start local stdio servers; Perplexity says it requires user consent and local MCP must be enabled. — [SecurityWeek](https://www.securityweek.com/squarex-and-perplexity-quarrel-over-alleged-comet-browser-vulnerability/)
- [P-press] Zenity's framing: "Hard boundaries are the only reliable prevention layer in agentic AI security"; define hard limits first (file system, network egress, credentials, code execution), enforce outside the model, then add soft guardrails. — [Zenity, 2026-03-13](https://zenity.io/blog/security/hard-boundaries-agentic-ai)

### Inferences
- Trade-off summary: main profile = full utility, SOP effectively delegated to the model; separate profile / logged-out = SOP-equivalent protection for existing sessions but the agent cannot do account-bound tasks unless the user logs in again inside the agent context (which rebuilds the exposure for those sites only); remote cloud browser = protects the local machine, files and other sessions, but the session the user logs into remotely is still exposed and credentials transit a vendor-hosted browser.
- Screenshot-only perception limits what an injection can read (no masked fields, no hidden DOM) but exposes the agent to visual-only injections; DOM access is the reverse. Products mixing both (Claude, Atlas) take both risks.
- Passkeys were not mentioned in any vendor document I read; credential mediation is described only for passwords, form fill and payment methods.
- Local-network (RFC1918/localhost) access by agents is not addressed in any source read; only `file://` and internal `chrome://`-style pages are documented as blocked.

### Gaps
- No vendor documents how passkeys/WebAuthn prompts are handled when an agent drives the page.
- No source on agent access to localhost/intranet addresses or on Private Network Access interplay.
- Cookie/session scoping for Chrome's "remote browser" (which cookies are copied, how) not documented in what I read.
- Native-messaging host trust for Claude in Chrome ↔ Claude Desktop/Claude Code not researched beyond the admin toggle.
- Roesner & Kohlbrenner tested Brave Leo and Edge Copilot in non-agentic form; Brave AI browsing and Edge Agent Mode were not covered by an independent SOP test.

Root-cause classes:
- **A. Content-as-instruction** (page text, hidden text, images, invites, puzzles): Operator (Feb, Dec 2025), Comet (Brave ×2, PleaseFix entry point), Fellou, Opera Neon, BrowserOS, BioShocking, Gemini Trifecta.

- **C. Memory persistence / CSRF**: Tainted Memories; cross-origin chat-memory poisoning concept (Roesner & Kohlbrenner).
- **D. Extension / trusted-origin boundary**: CVE-2026-0628, ShadowPrompt, ClaudeBleed, Manifold, BragJack (five products), SquareX MCP API.
- **E. Phishing / scam susceptibility**: Scamlexity; LayerX phishing-block comparison.

### Inferences
- Class A findings were mostly met with model/classifier updates and frequently re-opened; class D and F findings were met with code changes, version numbers, CVEs and bounties. The industry treats only the latter as "vulnerabilities" in the classical sense, which also explains why OpenAI declined a report lacking a working injection.
- Every extension-style or panel-style integration examined in 2026 failed the same way: authenticating the command channel by web origin rather than by execution context. This is a design monoculture issue (the CSA note's term), independent of model quality.
- Fix quality varied by vendor: Google and Microsoft issued CVEs and versioned fixes; Perplexity fixed critical items but disputed or closed others; Anthropic shipped fixes that two research teams called incomplete and paid the smallest bounty; smaller vendors (Fellou, Genspark, Sigma) did not respond.
- The Comet `file://` case shows a full chain from class A to class F and shows that a deterministic block still needed a second iteration (scheme-prefix bypass).

### Gaps
- Primary write-ups not opened: Forever Security (BragJack), Koi (ShadowPrompt), LayerX's own posts for CometJacking/ClaudeBleed/BioShocking (site now redirects to Akamai), NeuralTrust, Cato HashJack, SquareX, Embrace The Red, Manifold, Opera's security blog. Rows marked [S] or [P-press] should be re-verified before verbatim quoting.
- BioShocking publication date conflicts (24 Jun vs 30 Jun 2026) and product count (six vs five-plus-one) across secondary sources.
- BragJack bounty for Anthropic reported as $600 and as $500; total as about $20,000 and $20,500.
- HashJack per-vendor fix dates, and whether OpenAI fixed the omnibox and memory-CSRF issues, not established.
- CVE-2026-55945 not checked against Microsoft's advisory.
- No primary-sourced in-the-wild exploitation or loss was found for any item; aggregator claims to that effect were not used.

## 7. Independent evaluations of browser agents with production safeguards on

### Takeaway
Independent evaluation of shipped browser agents with safeguards enabled is thin: one academic capability/SOP study of seven products (qualitative, one full exploit), one manual student-team scorecard of five products, vendor-on-competitor tests by security companies, and Anthropic's own in-harness numbers. No independent, adaptive, statistically powered benchmark of production agentic browsers exists in what I found.

### Cited Findings
- [P] Roesner & Kohlbrenner (UW; ICLR 2026 Workshop on Agents in the Wild; tests late Jan–early Feb 2026, latest stable versions, macOS): manual tests on two-domain test sites against Brave Leo, Atlas (with and without agent mode), Chrome with Gemini, Claude for Chrome, Edge with Copilot, Firefox AI Mode, Comet. Result: full cross-origin theft PoC on Atlas agent mode; preconditions present for Chrome (auto browse), Claude, Comet, where a naive "do what the page says" injection was refused "due to model guardrails". The authors state their goal "was not to develop sophisticated prompt injections". — [paper](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf)
- [P] AgentWatch (UC Berkeley CLTC white paper, June 2026; master's capstone, six authors): manual prompts by human testers against Atlas, Claude, Comet, Copilot, Gemini using clean user profiles; rubric scores 0–1 per task. Overall composite (0–100): Claude 97.3, Atlas 93.6, Gemini 92.9, Comet 86.1, Copilot 77.7. Prompt-injection dimension: Claude 1.00, Atlas 0.95, Copilot 0.81, Gemini 0.78, Comet 0.67. Stated limits: manual testing means few rounds and "potentially less statistically significant results", evaluator variance, non-static models. Atlas resisted obvious injections but showed "weakness in indirect prompt injection scenarios". — [CLTC AgentWatch](https://cltc.berkeley.edu/wp-content/uploads/2026/06/AgentWatch.pdf)
- [P] LayerX (security vendor) phishing exposure test, Oct 2025: 103 in-the-wild malicious pages; Atlas allowed 97 (blocked 5.8%), Edge blocked 53%, Chrome 47%; Comet and Genspark 7% in an earlier run. This measures built-in anti-phishing of the browser shell, not agent hijack. — [LayerX via Akamai, 2025-10-27](https://www.akamai.com/blog/security/2025/oct/layerx-identifies-vulnerability-in-new-chatgpt-atlas-browser)
- [P-press] Guardio Scamlexity (Aug 2025): three scenarios against Comet, run "multiple times" with mixed outcomes; no rates published. — [Guardio](https://guard.io/labs/scamlexity-we-put-agentic-ai-browsers-to-the-test-they-clicked-they-paid-they-failed)
- [P] Vendor self-evaluation in the production harness (for contrast): Anthropic, Cowork harness with auto mode, 0/110 scenarios (Opus 5.5) — attacks authored by contracted professional red-teamers, transferred from Opus 4.7. — [Opus 5.5 System Card](https://anthropic.com/claude-opus-5-5-system-card)
- [P] Perplexity's BrowseSafe-Bench evaluates the detector (F1 about 0.91), not end-to-end agent compromise. — [Perplexity](https://www.perplexity.ai/hub/blog/browsesafe)
- [P-press] Cross-vendor disclosure practice: only Anthropic publishes per-surface injection rates with and without safeguards; OpenAI gives one connector robustness score; Google gives none. — [VentureBeat, 2026-06-01](https://venturebeat.com/security/anthropic-browser-agent-hijacked-31-percent-before-safeguards-engaged)
- (From earlier notes, bare-model or API-harness rather than shipped browsers: RedTeamCUA Operator with checks 7.57% vs 30.89% without; SIR 24% on Opus 4.8; Saban 0/140.) — see `threats_and_attacks.md`.

### Inferences
- What remains unmeasured: (1) adaptive attackers against shipped Chrome auto browse, Edge Agent Mode, Comet and Brave AI browsing with safeguards on; (2) the effect of human confirmation under realistic attention (approval fatigue, watch-mode lapses); (3) end-to-end rates per permission mode (Manual/Auto/Skip; Balanced/Strict); (4) long-horizon and memory-mediated attacks; (5) non-English and visual-only injections at scale (BrowseSafe's own numbers show a multilingual drop to 76%); (6) attack classes B–F, which benchmarks built around page-content injection do not cover at all.
- The two independent studies disagree in emphasis with vendor numbers but not in substance: both find top products refuse naive injections, and both find residual weaknesses outside that test (architecture in the UW study, indirect phrasing in AgentWatch).
- Terms of service, bot detection and rapid product churn (Atlas retired within ten months) make reproducible third-party benchmarking of shipped browsers hard; this is a structural reason for the gap.

### Gaps
- No arXiv paper from 2026 was found that benchmarks multiple shipped agentic browsers with production safeguards using an automated or adaptive attacker. Two searches; absence not proven.
- AgentWatch task counts per dimension were not extracted; treat its decimals as coarse.
- Brave's Black Hat USA 2026 talk (Chaikin) may contain cross-browser test results; the only article found returned 403.

## 8. Enterprise controls and analyst advice

### Takeaway
By late 2026 each major vendor offers an on/off switch plus site allow/block lists for its browser agent, and the enterprise-first products default to off (Chrome auto browse for managed users, Edge Copilot/Agent Mode, Claude for HIPAA tenants) — but action-level audit logging and DLP integration are documented clearly only for Edge (DLP) and OpenAI's ChatGPT Work (Compliance API). Gartner's December 2025 advice to block AI browsers has not, in anything I could find, been withdrawn.

### Cited Findings
- [P] Chrome Enterprise: `GeminiSettings`, `GenAiDefaultSettings`, `GeminiActOnWebSettings`, `GeminiActOnWebAllowedForURLs`, `GeminiActOnWebBlockedForURLs`, `GeminiSparkSettings`; auto browse "off by default for managed users"; Workspace data-protection controls apply; logging/audit and DLP for auto browse not described on the page. — [Chrome Enterprise Help](https://support.google.com/chrome/a/answer/16291696)
- [P] Edge for Business: Copilot Mode not auto-enabled; Agent Mode separately enabled with an admin list of approved sites; honours DLP and usage-rights restrictions (user is told a protected page cannot be accessed); no saved passwords or payment methods; Microsoft 365 Copilot licence required; managed through the Edge management service in the Microsoft 365 admin center. — [Edge Blog, 2025-11-18](https://blogs.windows.com/msedgedev/2025/11/18/edge-for-business-presents-the-worlds-first-secure-enterprise-ai-browser/)
- [P] Claude Team/Enterprise: org toggle; allowlist and blocklist; per-role capability (Enterprise custom roles); `forceLoginOrgUUID` Chrome policy; managed deployment through Chrome management tools; Team and Enterprise on by default (HIPAA tenants off); ZDR unsupported; a manually typed blocked URL still loads but Claude's tools are disabled there. — [Claude Help: admin controls](https://support.claude.com/en/articles/13065128-claude-in-chrome-admin-controls)
- [P-press] OpenAI: Lockdown Mode is assigned by admins through a dedicated role; ChatGPT Work admins control access, connected tools, permitted actions, browser/network access for cloud environments, spend limits, and get a Compliance API covering "conversations and actions". — [Help Net Security, 2026-02-16](https://www.helpnetsecurity.com/2026/02/16/chatgpt-lockdown-mode-elevated-risk/); [PPC Land](https://ppc.land/openai-kills-atlas-browser-folds-it-into-new-chatgpt-work-agent/)
- [P-press] Gartner, "Cybersecurity Must Block AI Browsers for Now" (Dennis Xu, Evgeny Mirolyubov, John Watts; early Dec 2025): "Default AI browser settings prioritize user experience over security"; risks named include "indirect prompt-injection-induced rogue agent actions" and "further loss and abuse of credentials" if led to a phishing site; sidebar data "is often sent to the cloud-based AI back end"; recommendations: block installs where the back end is judged too risky; if approved after assessment, educate users that "anything they are viewing could potentially be sent to the AI service back end", limit agent abilities (e.g. no email), use settings that prevent data retention; expect a long list of prohibited use cases and fleet monitoring. — [The Register, 2025-12-08](https://www.theregister.com/2025/12/08/gartner_recommends_ai_browser_ban/)
- [S] No revised Gartner position found in 2026: the piece was republished in Japanese in Feb 2026 under the same thesis, and an Oct 2026 secondary summary says Gartner states organisations with low risk tolerance "may need to block AI browsers for the long term". — [ITmedia, 2026-02-20](https://atmarkit.itmedia.co.jp/ait/articles/2602/20/news005.html); [SecurePrivacy guide, 2026-11](https://secureprivacy.ai/blog/ai-browser-security-governance-guide)
- [P-press] Counter-view recorded by Wiz: a blanket block risks a "Department of No" culture; recommended practice is to isolate browsing contexts from primary credentials, keep confirmations on and limit use to low-stakes tasks. — [Wiz, 2026-01-16](https://www.wiz.io/blog/agentic-browser-security-2025-year-end-review)
- [P] Academic user advice (Apr 2026): proceed with caution because "the security models have not yet been worked out"; Brave, Edge and Firefox assistants have fewer agentic features but stronger security at present. — [UW project page](https://agent-security.cs.washington.edu/agentic_browsers_sop.html)

### Inferences
- The practical enterprise posture available in Nov 2026 is: agent off by default; enable per group; restrict to an approved-site list; keep credentials and payment data out of reach; prefer vendors whose restrictions are enforced by the browser binary or tenant policy rather than by the model.
- A malicious or compromised extension is now a first-class threat to browser agents (class D in section 6), so extension allowlisting belongs in the same policy set as the agent toggle; none of the vendor admin pages I read makes that link.
- Because agentic features moved into Chrome, Edge and extensions for existing browsers, "block AI browsers" by blocking installers no longer covers the risk; control has to be exercised through browser policies and extension management.

### Gaps
- Gartner's own text and any 2026 revision were not read (paywalled); statements come from press.
- Action-level audit logs for Chrome auto browse, Edge Agent Mode and Claude in Chrome: not documented in the pages read (Chrome history icon and Claude Compliance API coverage are the only leads, the latter from a third party).
- No source on third-party DLP/SSE/enterprise-browser products inspecting agent actions (as opposed to user actions) was examined.
- Chrome Enterprise Premium's agent-specific protections (beyond shadow-IT detection) were not verified.
