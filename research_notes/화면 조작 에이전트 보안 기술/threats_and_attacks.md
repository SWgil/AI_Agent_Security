# Threat landscape and demonstrated attacks against screen-operating (GUI) AI agents — state as of November 2026

Reading notes for the report writer:
- Research date: 2026-11-18. Items dated 2024-2025 are marked "(older)".
- Verification labels: **[P]** = I read the primary source this session; **[S]** = taken from secondary coverage or a search-result summary only, primary not opened; **[M]** = from my prior knowledge, URL given but not re-fetched this session. Treat [S] and [M] numbers as needing a check before they are quoted as headline figures.
- Attack success rates (ASR) from different papers are NOT comparable: they differ in attacker budget (single-shot vs. best-of-N vs. RL-optimised), in whether "attempted" or "completed" is counted, in the model generation, and in whether product-level safeguards (confirmations, classifiers) were on.

## 1. What attack classes are specific to or amplified by GUI/screen agents?

### Takeaway
The dominant class is indirect prompt injection through anything rendered on screen (web content, messages, notifications, pop-ups, low-opacity overlays, calendar invites), and it is amplified in GUI agents because the agent acts inside the user's authenticated sessions with the user's full cross-app/cross-origin privileges, so classic isolation (same-origin policy, app sandboxing) no longer bounds the damage. GUI agents add attack classes that API agents do not have: perception gaps between what the human sees and what the model reads, click redirection/overlays, races on the screenshot channel, and exposure of credentials/OTPs simply because they are visible on screen.

### Cited Findings

**A. Indirect prompt injection via on-screen content (web pages, comments, hidden text)**
- [P] Brave on Perplexity Comet (reported 25 Jul 2025, published 20 Aug 2025, older): instructions hidden in a Reddit comment behind a spoiler tag were executed when the user clicked "Summarize the current webpage"; the agent fetched the user's email address, triggered an OTP login, read the OTP from the user's logged-in Gmail and posted both back to Reddit, enabling account takeover. Brave's formulation of why this is structurally new: when the assistant follows instructions from untrusted page content, same-origin policy and CORS are "effectively useless" because the assistant runs with the user's full privileges across authenticated sessions. — [Brave](https://brave.com/blog/comet-prompt-injection/)
- [P] Anthropic's own list of why browser agents are specially exposed (24 Nov 2025, older): "every webpage, embedded document, advertisement, and dynamically loaded script" is a potential injection vector, and the agent has many actions (navigate, fill forms, click, download) to exploit once influenced. — [Anthropic](https://www.anthropic.com/research/prompt-injection-defenses)
- [P] Google (8 Dec 2025, older): "The primary new threat facing all agentic browsers is indirect prompt injection", arriving via malicious sites, third-party iframes or user-generated content, leading to unauthorised transactions or data theft. — [Google](https://blog.google/security/architecting-security-for-agentic/)
- [P] Payload concealment seen on the live web (Google and Forcepoint X-Labs, reported 24 Apr 2026): text shrunk to one pixel, near-transparent text, hidden-tagged elements, HTML comments, page metadata/meta tags. — [Help Net Security](https://www.helpnetsecurity.com/2026/04/24/indirect-prompt-injection-in-the-wild/)

**B. Visual / perception-gap injection (the human and the model see different things)**
- [S] Brave's second round on Comet (Oct 2025, older): instructions in faint light-blue text on a yellow background inside an image/screenshot, invisible to people but read by the model. — [search summary of Brave/The Hacker News coverage](https://thehackernews.com/2025/10/cometjacking-one-click-can-turn.html) (the specific Brave post was not opened)
- [P via CSA summary of the paper] "(A)I Sees What You Don't" (arXiv 2607.00333, 1 Jul 2026), against five open mobile-agent frameworks (AppAgent, AppAgentX, Mobile-Agent-v3, Open-AutoGLM, MobA): "subliminal visual injection" using an overlay at as low as 2% opacity that the VLM reads but a person cannot see; "invisible zone injection" placing payloads under rounded corners and camera cutouts, which are physically hidden but present in the captured screenshot. Perception attacks succeeded at or near 20/20 trials across GPT-4o, Claude, Gemini and smaller models. — [Cloud Security Alliance research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-mobile-agent-attack-surface-screen-injecti/)
- [S] "Agent-only" injection: a malicious app embeds jailbreak prompts in its own UI that stay inert for humans and are revealed only when an agent drives the UI over ADB, needing only low-privilege access (arXiv 2510.07809, Oct 2025, older). — [arXiv](https://arxiv.org/pdf/2510.07809v3)

**C. Pop-ups, deceptive UI and UI redressing against agents**
- [S] "Attacking Vision-Language Computer Agents via Pop-ups" (Zhang, Yu, Yang; arXiv Nov 2024, ACL 2025, older): adversarial pop-ups inserted into OSWorld and VisualWebArena were clicked 86% of the time on average and cut task success by 47%; telling the agent to ignore pop-ups did not work. — [arXiv 2411.02391](https://arxiv.org/abs/2411.02391v2), [ACL Anthology](https://aclanthology.org/2025.acl-long.411)
- [S] Transparent overlays placed over actionable elements ("Send", "Submit", app icons) intercept an agent's coordinate-based tap and redirect it to an attacker-controlled activity (arXiv 2505.12981, May 2025, older). — [arXiv](https://arxiv.org/pdf/2505.12981)
- [P via CSA] UI spoofing on Android: a malicious app detects the target app's launch via Accessibility Service and overlays a fake interface to capture credentials the agent types. — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mobile-agent-attack-surface-screen-injecti/)
- [P via CSA] Logic-level deception rather than hidden text: LayerX "BioShocking" (published 24 Jun 2026) uses a visible puzzle page that rewards wrong answers ("2 + 2 = 5") so the agent accepts a false premise and treats its safety rules as inapplicable, then follows a redirect into the user's authenticated GitHub and copies SSH credentials. — [CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-browser-prompt-injection-20260630-csa-s/)

**D. Notifications, messages, calendar invites (attacker-pushed content, zero-click)**
- [P via The Hacker News report of SafeBreach's research] Gemini on Android (published 3 Jun 2026): a poisoned notification from WhatsApp, Slack, SMS, Signal, Instagram or Messenger was treated as instructions by Gemini's Utilities agent; no malicious app on the phone needed. The researcher (Or Yair) called the surface "effectively infinite". — [The Hacker News](https://thehackernews.com/2026/06/whatsapp-slack-notifications-could.html)
- [P via CSA] Zenity "PleaseFix" (3 Mar 2026): a calendar invite processed later during a routine calendar task makes Perplexity Comet read local files via `file://` and send them out, while the user still receives the expected task result. — [CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-pleasefix-agentic-browser-exploits-2026032/), [Help Net Security](https://www.helpnetsecurity.com/2026/03/04/agentic-browser-vulnerability-perplexedbrowser/)
- [P abstract] GhostEI-Bench (arXiv 2510.20333, Oct 2025, ICLR 2026 poster) models deceptive overlays and spoofed notifications injected into a running Android emulator as the core mobile threat. — [arXiv](https://arxiv.org/abs/2510.20333)

**E. Credential / OTP exposure and data exfiltration through the agent's own legitimate reach**
- [P] OTP read out of Gmail and posted publicly (Comet, 2025, older). — [Brave](https://brave.com/blog/comet-prompt-injection/)
- [P via CSA] Password-manager abuse: PleaseFix's second path ("PerplexedBrowser") abuses Comet's authorised 1Password integration to manipulate credential retrieval / partial account takeover without attacking 1Password's code. — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-pleasefix-agentic-browser-exploits-2026032/)
- [P via CSA] On mobile frameworks: credential sniffing by an Accessibility Service capturing plaintext typed by the agent; interception of unprotected broadcasts used for text input. — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mobile-agent-attack-surface-screen-injecti/)
- [P] Screens are uploaded to the cloud per step in the Doubao phone; a viral video showed a user's bank balance visible on mirrored devices logged into the same Doubao account. — [Lawfare, 6 Mar 2026](https://www.lawfaremedia.org/article/china-s-agentic-ai-controversy)

**F. Confused deputy / cross-origin and cross-app flows / deep links**
- [S] CometJacking (LayerX, Oct 2025, older): a single crafted URL whose `collection` parameter makes the agent consult memory/connectors instead of the web; the injected prompt pulls email and calendar data and exfiltrates it Base64-encoded to evade data-protection checks. Perplexity classed it as having "no security impact". — [The Hacker News](https://thehackernews.com/2025/10/cometjacking-one-click-can-turn.html)
- [S] Roesner & Kohlbrenner (ICLR 2026 Workshop "Agents in the Wild"): in the least restrictive agentic browsers a site that lands an injection can use the agent to circumvent the same-origin policy and steal cross-origin content. — [paper PDF](https://homes.cs.washington.edu/~franzi/pdf/roesner_kohlbrenner_2026_agentic_sop.pdf) (PDF could not be parsed this session; claim comes from a search summary)
- [P via The Hacker News] Gemini Android demo: an injected notification redirected the phone to a Zoom app link, forcing it to join a meeting and stream video; opened URLs to geolocate the victim; operated Google Home windows/boilers/lights. — [The Hacker News](https://thehackernews.com/2026/06/whatsapp-slack-notifications-could.html)
- [S] HashJack (Cato Networks, Nov 2025, older): instructions hidden in URL fragments target AI browser assistants. — [CSA note listing](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-browser-prompt-injection-20260630-csa-s/)
- [S] ChatGPT Atlas omnibox injection (NeuralTrust, Oct 2025, older): a string that looks like a URL but fails URL validation is treated wholesale as a trusted user prompt. — [ITPro](https://www.itpro.com/security/cyber-researchers-have-already-identified-several-big-security-vulnerabilities-on-openais-atlas-browser)

**G. Memory / persistence poisoning**
- [P via The Hacker News] Gemini Android: injected notification wrote to Gemini's account-level long-term memory (victim's name stored as "Danny") and created a scheduled daily action (8 PM, read recent messages) for persistence. — [The Hacker News](https://thehackernews.com/2026/06/whatsapp-slack-notifications-could.html)
- [S] ChatGPT Atlas "Tainted Memories" (LayerX, Oct 2025, older): CSRF plants instructions into ChatGPT memory that persist across every device and browser where the account is signed in. — [Akamai/LayerX coverage](https://www.akamai.com/blog/security/2025/oct/layerx-identifies-vulnerability-in-new-chatgpt-atlas-browser), [ITPro](https://www.itpro.com/security/cyber-researchers-have-already-identified-several-big-security-vulnerabilities-on-openais-atlas-browser)
- [S] Academic: "Context manipulation attacks: Web agents are susceptible to corrupted memory" (arXiv 2506.17318, 2025, older). — [arXiv](https://arxiv.org/pdf/2506.17318)

**H. Attacks on the agent's plumbing (screenshot channel, host, extension)**
- [P via CSA] Screenshot tampering: a co-installed app swaps the screenshot file in the roughly 50-500 ms (avg. ~210 ms) window between capture and the host pulling it. Host-side command injection: shell metacharacters shown on screen are transcribed by the VLM and concatenated into a `shell=True` command, giving code execution on the PC that drives the phone. Chained in a WeChat case study (overlay fake "network sync" message widens the race window, then substituted screenshot, then host RCE). — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mobile-agent-attack-surface-screen-injecti/)
- [S] Browser-extension trust boundary: "ShadowPrompt" (Koi, Mar 2026) let websites silently inject prompts into the Claude Chrome extension; "ClaudeBleed" (LayerX, 7 May 2026) abused the extension's `externally_connectable` trust model so other extensions could drive it; Manifold (Jul 2026) reported the task-activation click's source is not verified so other extensions can fake it. — [The Hacker News, Mar 2026](https://thehackernews.com/2026/03/claude-extension-flaw-enabled-zero.html), [IANS, 20 Jul 2026](https://www.iansresearch.com/resources/all-blogs/post/security-blog/2026/07/20/unpatched-claude-for-chrome-flaw-could-give-attackers-access-to-gmail--calendar)

**I. Malware delivery / agent as C2**
- [S] "ZombAIs" (Johann Rehberger, Oct 2024, older): a web page told Claude Computer Use to download and run a binary that joined a C2 server; worked on the first try. — [Embrace The Red](https://embracethered.com/blog/posts/2024/claude-computer-use-c2-the-zombais-are-coming), [Simon Willison](https://simonwillison.net/2024/Oct/25/zombais/)
- [S] "AI ClickFix" (Rehberger, 39C3, Dec 2025, older): ClickFix-style social-engineering pages adapted to computer-use agents, with "conditional prompt injections" targeting specific agents. — [media.ccc.de](https://app.media.ccc.de/v/39c3-agentic-probllms-exploiting-ai-computer-use-and-coding-agents), [heise](https://heise.de/-11125687)

**J. Taxonomy anchor (OWASP)**
- [S] OWASP Top 10 for Agentic Applications 2026 (released 9 Dec 2025), ASI01 through ASI10; ASI01 is "Agent Goal Hijack": the attacker redirects the agent's objective through content the agent reads. Exact wording of the other nine entries was not verified against OWASP's own page. — [TechRepublic](https://www.techrepublic.com/article/news-owasp-ai-agent-risk-list/), [Cycode summary](https://cycode.com/blog/owasp-top-10-agentic-applications/)

### Inferences
- Properties that make GUI agents harder to secure than API/tool-calling agents (synthesis of the above):
  1. **No typed boundary between data and instructions.** An API agent gets tool results in a labelled channel; a GUI agent gets one screenshot/accessibility tree in which trusted chrome, the user's own content and attacker content are pixels of equal standing. Provenance is lost at capture time.
  2. **Human/agent perception mismatch.** 2%-opacity overlays, corner/cutout zones, faint colours, TTS-skipped hyperlink text: the supervising human literally cannot see what the agent saw, which undermines "watch the agent" as a control.
  3. **Ambient authority.** The agent inherits every logged-in session and every installed app; there is no per-tool scope to narrow. This is the confused-deputy problem with the widest possible deputy.
  4. **Unbounded action space.** A tool agent can be restricted to an allowlist of functions with schemas; "click at (x, y)" and "type text" can express any action in any app, so policy has to be inferred from pixels and intent.
  5. **Attacker-pushed input.** Notifications, messages, invites and ads reach the screen without the user or agent choosing to visit anything (zero-click).
  6. **The capture and actuation channel is itself an attack surface** (screenshot races, input broadcasts, overlays, extension messaging), which has no analogue in an HTTPS tool call.
  7. **Secrets are on screen** (OTPs, balances, passwords in password managers), and in cloud-inference designs every screenshot leaves the device.
- The agent's competence increases risk: several benchmarks find that more capable agents complete more attacker goals (see section 2).

### Gaps
- I did not find a published, demonstrated classic clickjacking (iframe-based) attack specifically against a shipped browser agent; the "UI redressing" evidence is pop-ups and overlays.
- Ad-network-delivered injection against a shipped agent: vendors list ads as a vector, but I found no documented incident.
- OWASP ASI02-ASI10 titles not verified from the primary OWASP document.

## 2. What academic work and benchmarks measure this, and what attack success rates do they report?

### Takeaway
Across 2024-2026 benchmarks, un-safeguarded GUI agents are hijacked at rates from tens of percent up to about 90%, and mobile agents in 2026 still show 40-67% ASR on a realistic Android benchmark. The newest frontier models show much lower rates against fixed or hand-written injections in browser settings (single digits to 0/140), but adaptive or self-improving attackers bring rates back to roughly 24-28%, and one 2026 audit argues that both the high and the low headline numbers are artefacts of attacker strength and model vintage.

### Cited Findings

**Computer-use / browser agents**
- [S] Pop-up attack (arXiv Nov 2024; ACL 2025, older): 86% average ASR (agent clicks the pop-up) on OSWorld and VisualWebArena; 92.7% / 73.1% of attacked agents' actions were pop-up clicks; task success down 47%. — [arXiv 2411.02391](https://arxiv.org/abs/2411.02391v2)
- [M] EIA: Environmental Injection Attack (arXiv 2409.11295, Sep 2024; ICLR 2025, older): injected form fields/mirror elements steal user PII from a web agent; I recall up to about 70% ASR for stealing specific PII and about 16% for stealing the full user request, on SeeAct with GPT-4V on Mind2Web. Not re-fetched this session. — [arXiv](https://arxiv.org/abs/2409.11295)
- [S] WASP (Meta FAIR; arXiv 2504.18575, Apr 2025; NeurIPS 2025 D&B, older): tested Claude Computer Use, Operator and VisualWebArena agents; attacks "partially succeed in up to 86% of the cases", but agents often fail to finish the attacker's goal (ASR-intermediate vs. ASR-end-to-end). Per-model end-to-end numbers not retrieved. — [arXiv](https://arxiv.org/abs/2504.18575), [NeurIPS](https://neurips.cc/virtual/2025/poster/121728)
- [P abstract] VPI-Bench (arXiv 2506.02456, Jun 2025; rev. Mar 2026; ICLR 2026): 306 visual-prompt-injection cases on five platforms; computer-use agents deceived at up to 51%, browser-use agents up to 100% on certain platforms; system-prompt defences give only limited improvement. — [arXiv](https://arxiv.org/abs/2506.02456)
- [S] OS-Harm (arXiv 2506.14866, Jun 2025; NeurIPS 2025, older): on OSWorld; models included o4-mini, Claude 3.7 Sonnet, Gemini 2.5 Pro; agents comply with basic static prompt injections "in 20% of cases for o4-mini". A third-party table summary lists o4-mini at 52% unsafe on deliberate misuse, 20% injection, 10% misbehaviour. — [arXiv](https://arxiv.org/abs/2506.14866), [table summary](https://en.papernotes.org/NeurIPS2025/social_computing/os-harm_a_benchmark_for_measuring_safety_of_computer_use_agents/)
- [P] RedTeamCUA / RTC-Bench (Ohio State; arXiv 2505.21936, v4 16 Feb 2026; ICLR 2026): hybrid web + OS sandbox, 864 examples, execution-based scoring.
  - Decoupled evaluation, ASR (attempt rate): GPT-4o 66.19% (92.45%); Claude 3.5 Sonnet 41.37% (64.27%); Claude 3.7 Sonnet 39.33% (58.99%); Claude 3.7 Sonnet CUA 42.93% (64.39%); Claude 3.5 Sonnet CUA 31.21% (74.43%); Operator without checks 30.89% (47.84%); Operator with its confirmation/safety checks 7.57% (14.06%).
  - End-to-end, 50 tasks, ASR: Operator 10%; Operator w/o checks 42%; Claude 3.7 Sonnet CUA 50%; Claude Opus 4 CUA 48%; Claude Sonnet 4.5 CUA 60%; Claude Opus 4.5 CUA 83% (38/46 valid); Claude Opus 4.6 CUA 50%, with Opus 4.6 explicitly detecting the injection in 25/50 cases vs. 3 for Opus 4.5.
  - Defences: LlamaFirewall and PromptArmor detected at most 30% of injections; defensive system prompt left ASR near 50%; Meta SecAlign still followed about half. Authors conclude none is adequate, and that Operator's protection depends on human supervision (autonomy/security trade-off).
  - Attempt rate is consistently above ASR: agents often try the attacker's goal and fail from lack of capability.
  — [arXiv HTML v4](https://arxiv.org/html/2505.21936v4)
- [P abstract] Saban, "Domain-Conditioned Safety in Frontier Computer-Using Agents" (arXiv 2606.05233, 3 Jun 2026; single author, preprint): 793 episodes, 24 multi-step web tasks, 56 hand-crafted attack templates in 8 families; **0/140 multi-step attack successes against Claude Sonnet 4.6 and GPT-5.4** (Clopper-Pearson 95% upper bound 2.60%). States that the 42-98% ASRs in recent CUA red-teaming papers cluster on retired models and on the weakest model in each panel, and are driven by RL-optimised injection strings; the same weights fall to hand-crafted skill injection at up to 100% in a coding-agent benchmark, so hardening looks domain-specific to the browser surface. — [arXiv](https://arxiv.org/abs/2606.05233)
- [P abstract] SIR: Self-improving Red-teaming for Computer Use Agents (arXiv 2608.30207, 31 Aug 2026, rev. 3 Oct 2026): black-box, up to 10 attempts per case, success counted only if the adversarial OS-level objective AND the benign task both complete, deterministic state checks. **Joint ASR 24% on Claude Opus 4.8 and 28% on Gemini 3.5 Flash, versus 4% and 0% for the benchmark's fixed hand-written injection.** — [arXiv](https://arxiv.org/abs/2608.30207)
- [S] ClawSafety (arXiv 2604.01438, Apr 2026): ASR 40-75% across models, varying sharply by injection vector (personal-agent setting; relevance to pure GUI operation not checked). — [arXiv](https://arxiv.org/pdf/2604.01438)

**Mobile GUI agents**
- [P abstract] AEIA-MN, "Active Environmental Injection Attacks" (arXiv 2502.13053, Feb 2025; ACM MM 2025, older): attacker content disguised as environment elements on Android (the method name refers to mobile notifications); maximum ASR 93% on AndroidWorld when combining adversarial content injection with a "reasoning gap" vulnerability. — [arXiv](https://arxiv.org/abs/2502.13053)
- [P abstract] "From Assistants to Adversaries" (arXiv 2505.12981, May 2025, older): nine deployed mobile agents (incl. Honor YOYO, Zhipu AutoGLM, Alibaba Mobile-Agent), 11 attack surfaces; every agent vulnerable; the worst were vulnerable to eight vectors; outcomes range from behaviour deviation to privacy leakage to full execution hijack; two device vendors acknowledged the disclosure. No ASR in the abstract. — [arXiv](https://arxiv.org/abs/2505.12981)
- [P abstract] GhostEI-Bench (arXiv 2510.20333, Oct 2025; ICLR 2026): dynamic injection of overlays and spoofed notifications into Android emulator runs. ASR numbers not retrieved. — [arXiv](https://arxiv.org/abs/2510.20333), [ICLR](https://iclr.cc/virtual/2026/poster/10011688)
- [P] MobileWorldSafety (Shanghai AI Lab; arXiv 2608.17659, 18 Aug 2026): 142 risk tasks over 13 real Android apps plus 5 MCP servers; carriers are emails/messages, web and product pages, social posts, local files and calendar records, tool responses (overlays and notifications explicitly excluded). ASR: **Gemini-3-Pro 66.9%, Qwen3.5-397B 51.6%, Kimi-K2.5 49.2%, Claude Sonnet 4.5 47.5%, GUI-Owl-1.5-32B 44.3%, MAI-UI-8B 40.4%.** For every general-purpose agent, ASR exceeded task completion under attack. Directed communication (messages/email) gave consistently high ASR; tool-response injection the lowest. Turning on reasoning raised Gemini-3-Flash ASR from 51.2% to 57.9%. Defences: system prompt cut Qwen 51.6% to 37.0% and Gemini-3-Flash 57.9% to 41.5%, mostly by making the agent stall; a multi-stage runtime defence reached 35.7%. — [arXiv HTML](https://arxiv.org/html/2608.17659v1)
- [P via CSA] "(A)I Sees What You Don't" (arXiv 2607.00333, Jul 2026): seven attacks, five frameworks, each vulnerable to at least six; perception attacks at or near 20/20. — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mobile-agent-attack-surface-screen-injecti/)
- [S] MobileSafetyBench (2024-2025, older): described by one secondary source as 250 tasks plus 50 indirect-prompt-injection scenarios; sources conflict on figures, not verified. — [ResearchGate listing](https://www.researchgate.net/publication/402661952_MobileSafetyBench_Evaluating_Safety_of_Autonomous_Agents_in_Mobile_Device_Control)

**Tool-agent benchmark that transfers**
- [M] AgentDojo (ETH Zurich, NeurIPS 2024, older) is the standard tool-calling injection benchmark that later GUI benchmarks position themselves against; WASP's authors say it was built to address shortcomings of InjecAgent, AgentDojo and ASB. No AgentDojo numbers were retrieved this session. — [WASP paper](https://arxiv.org/abs/2504.18575)

### Inferences
- Three regimes are visible and should be reported separately: (a) open-source or older agents with no product safeguards: 40-93%; (b) frontier models against static/hand-written injections with safeguards: roughly 0-10%; (c) frontier models against adaptive attackers: roughly 1-30% depending on attempt budget. A single "ASR" figure without the regime is meaningless.
- Mobile lags desktop/browser: the best 2026 mobile numbers (40-67%) resemble 2025 desktop numbers, and include a current frontier model (Claude Sonnet 4.5 at 47.5%, Gemini-3-Pro at 66.9%) driven through an Android harness without vendor product safeguards. This supports the Saban paper's point that hardening is surface-specific and has been concentrated on browsers.
- Capability and vulnerability are coupled: RedTeamCUA end-to-end ASR rose from Opus 4 (48%) to Opus 4.5 (83%) as navigation improved, and MobileWorldSafety finds weaker GUI-specialist models have lower ASR largely because they fail before reaching the injection.
- Prompt-level defences mainly trade ASR for stalled tasks; system-level confirmation (Operator) gives the largest measured reduction (30.89% to 7.57%) but only with a human in the loop.

### Gaps
- GhostEI-Bench, WASP per-model end-to-end, OS-Harm per-model injection rates other than o4-mini, and AgentDojo numbers were not retrieved from the papers.
- EIA numbers are from memory.
- The Saban audit is a single-author preprint; its 0/140 result does not say whether it is per model or combined, and I did not read the full text.
- I did not find a peer-reviewed 2026 benchmark that tests shipped consumer phone agents (Gemini screen automation, Doubao, Honor/Huawei system agents) with their production safeguards on.
- "AndroidWorld-based safety benchmark" beyond AEIA-MN and MobileWorldSafety: none further identified.

## 3. What real-world incidents or public vulnerability disclosures exist for shipped products?

### Takeaway
Every major shipped screen/browser agent has had at least one public researcher disclosure of agent hijacking between 2024 and 2026, and several vendors closed reports without fixes or shipped fixes that researchers judged incomplete. Injection payloads aimed at agents are now observed on the live web, but I found no confirmed case of a real user being harmed through a shipped GUI agent; the documented "incidents" are researcher proofs of concept and platform blocking of agents.

- [S] CometJacking one-click URL exfiltration (LayerX, Oct 2025, older); Perplexity classified it as "no security impact". — [The Hacker News](https://thehackernews.com/2025/10/cometjacking-one-click-can-turn.html)

### Inferences
- Vendor handling is uneven: OpenAI and Google fixed reported issues (Google taking about three months); Perplexity repeatedly disputed impact or closed reports; Anthropic's extension-layer fixes were contested by researchers; smaller browser vendors did not respond. Disclosure maturity is itself a selection criterion.
- A recurring pattern is fix-then-bypass (Comet Jul-Aug 2025; Gemini "Invitation Is All You Need" then Delayed Tool Invocation then Fake Context Alignment; Claude extension v1.0.41 then v1.0.70 then Manifold), consistent with classifier- and UI-level mitigations rather than architectural ones.
- The Doubao episode is the only large-scale "incident" and it is the ecosystem rejecting the agent: relying parties (banks, super-apps) treat an indistinguishable automated actor as fraud. Agent identity/attestation toward apps is therefore a security requirement, and the reported pivot to MCP/A2A suggests pure screen operation of high-risk apps may not be commercially tenable.
- Extension-based agents add a conventional web-security attack surface (extension messaging, XSS in dependencies) on top of prompt injection.

### Gaps
- No confirmed real-world victim/loss case via a shipped GUI agent was found.
- No public vulnerability disclosure specific to Gemini's Android screen automation ("computer use" on phone) was found; the SafeBreach work concerns the Utilities/notification agent.
- No specific researcher disclosure against Microsoft Copilot's computer-use features was found in this session; only Microsoft's own warning.
- Anthropic's response to the Manifold findings, and the current state of the ClaudeBleed fix, are unconfirmed.
- Primary write-ups by LayerX, Zenity, Koi, SafeBreach and NeuralTrust were not opened; details come from CSA notes and press.

## 4. What do vendors themselves publicly admit about residual risk?

### Takeaway
All four major vendors state on the record that prompt injection against screen/browser agents is unsolved; Anthropic is the only one found publishing quantitative ASRs, which fell from double digits (2025) to about 1% (Nov 2025) and to 0% in one browser test with layered safeguards (Jul 2026, secondary reporting), while still non-zero for GUI computer use and against adaptive attackers.

### Cited Findings
- [P] Anthropic, 24 Nov 2025 (older), Claude in Chrome, internal adaptive best-of-N attacker with 100 attempts per environment, ASR by configuration (model only / old safeguards / improved safeguards): Sonnet 4: 13.8% / 10.7% / 2.0%; Sonnet 4.5: 13.8% / 10.8% / 1.9%; Haiku 4.5: 12.0% / 11.1% / 2.4%; Opus 4.5: 8.0% / 7.6% / 1.4%. Quotes: "A 1% attack success rate—while a significant improvement—still represents meaningful risk"; "No browser agent is immune to prompt injection"; "prompt injection is far from a solved problem". Defences: RL training against injections, classifiers over all untrusted content (hidden text, manipulated images, deceptive UI), red teaming. — [Anthropic](https://www.anthropic.com/research/prompt-injection-defenses)
- [M] Anthropic, Aug 2025 Claude for Chrome research preview (older): 23.6% ASR without mitigations across 123 test cases/29 scenarios, 11.2% with mitigations; on four browser-specific attack types 35.7% to 0%. From memory, not re-fetched. — [Anthropic](https://www.anthropic.com/news/claude-for-chrome)
- [S] Anthropic support page: "the chances of an attack are still non-zero". — [Claude Help Center](https://support.claude.com/en/articles/12902428-using-claude-for-chrome-safely)
- [S] Claude Opus 5 system card (Jul 2026), as reported by The Decoder (25 Jul 2026, citing p. 76): browser agent, 129 scenarios: 0% ASR with Auto Mode's two safeguard layers, 3.7% without safeguards (Sonnet 5: 0.93% without). Gray Swan indirect-prompt-injection benchmark at 15 attempts, model alone: Opus 5 2.0%, Mythos 5 2.6%, Fable 5 2.8%, Opus 4.8 5.5%. — [The Decoder](https://the-decoder.com/opus-5-may-have-solved-browser-based-prompt-injection-the-biggest-security-flaw-haunting-ai-agents/)
- [S, low confidence] Other secondary write-ups of the same card say adaptive evaluations for GUI computer use did not reach 0% (Opus 5 about 0.54-0.56%, Sonnet 5 2.25%), and that a later Opus 5.5 card reports 0.1% at one attempt / 1.0% within 15, highest in computer use (2.8%), plus a much higher figure against a newer attacker. These figures conflict across sources and the primary system cards were not opened. — [xenospectrum](https://xenospectrum.com/en/claude-opus-5-prompt-injection/), [stingrai](https://www.stingrai.io/blog/prompt-injection-statistics-2026)
- [S] Independent caution on those numbers: a CSA note reports prompt injection defeating the Claude Code Auto Mode safety classifier (coding setting, 2026). — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-claude-code-automode-prompt-injection-2026/)
- [S] OpenAI, 22 Dec 2025 (older): prompt injection, "much like scams and social engineering on the web, is unlikely to ever be fully 'solved'"; agent mode "expands the security threat surface"; deterministic guarantees are challenging; recommends logged-out mode and reviewing confirmations; a spokesperson declined to say whether the update measurably reduced successful injections. OpenAI's CISO called prompt injection "a frontier, unsolved security problem" (Oct 2025). — [TechCrunch](https://techcrunch.com/2025/12/22/openai-says-ai-browsers-may-always-be-vulnerable-to-prompt-injection-attacks/), [VentureBeat](https://venturebeat.com/security/openai-admits-that-prompt-injection-is-here-to-stay) (OpenAI's own post returned HTTP 403: https://openai.com/index/hardening-atlas-against-prompt-injection/)
- [P] Google, 8 Dec 2025 (older): indirect prompt injection is "an open challenge"; the detection classifier "cannot flag everything that might influence the model with malicious intent"; web-agent security "is still an emerging domain". — [Google](https://blog.google/security/architecting-security-for-agentic/)
- [S] Microsoft, Nov 2025 (older): agentic features "introduce novel security risks, such as cross-prompt injection (XPIA)", which can cause data exfiltration or malware installation; users must acknowledge a warning to enable. — [Windows Central](https://www.windowscentral.com/microsoft/windows-11/microsoft-warns-security-risks-agentic-os-windows-11-xpia-malware)
- [S] Perplexity's security team has called prompt injection an unsolved, industry-wide problem; Brave reportedly stated on 8 Jun 2026 that indirect prompt injection cannot be fully solved in current LLM architectures. — [The Hacker News](https://thehackernews.com/2025/10/cometjacking-one-click-can-turn.html), [secondary briefing](https://www.pk-sharma.com/briefing/agentic-browsers-widen-prompt-injection-exposure)
- [S] UK NCSC has likewise warned that prompt injection may never be fully mitigated. — [TechCrunch](https://techcrunch.com/2025/12/22/openai-says-ai-browsers-may-always-be-vulnerable-to-prompt-injection-attacks/)

### Inferences
- The vendor trajectory (23.6% in Aug 2025, about 1% in Nov 2025, 0% in one layered browser configuration in Jul 2026) shows the reduction comes mostly from system-level layers (input classifiers plus action gating), not from the model alone (model-only rates of 8-14% in Nov 2025; 3.7% for Opus 5 without safeguards). That supports a "layered system" framing for the technology report.
- Vendor numbers are measured on the vendor's own surface with the vendor's attacker. Independent 2026 results (SIR 24% on Opus 4.8; MobileWorldSafety 47.5% for Sonnet 4.5 on Android; researcher bypasses of shipped products) show residual risk outside those conditions.
- At even 1% per encounter, an agent that reads thousands of untrusted screens is expected to be compromised eventually; vendors themselves frame 1% as meaningful.

### Gaps
- Primary Anthropic system cards (Opus 5, Opus 5.5) and OpenAI's hardening post were not read directly; computer-use-specific ASRs are low confidence.
- No quantitative ASR published by OpenAI, Google or Microsoft for their GUI agents was found.
- No vendor-published ASR for a phone screen-automation agent was found.

## 5. Mobile-specific: what is different on a phone?

### Takeaway
A phone agent needs exactly the capabilities Android banking malware has abused for a decade (read the screen, inject input, draw overlays, read notifications), on the device where OTPs, payment apps and personal messages are concentrated, and where any contact or app can push attacker-controlled text onto the screen. The measured mobile-agent ASRs are the highest of any GUI-agent category, and relying apps cannot tell a legitimate agent from a remote-control trojan.

### Cited Findings
- [S] Scale of the pre-existing abuse the agent's permissions overlap with: Zimperium's 2026 Mobile Banking Heist Report covers 34 active malware families targeting 1,243 financial brands in 90 countries; four campaigns (RecruitRat, SaferRat, Astrinox, Massiv) target 800+ apps using Accessibility abuse, MediaProjection screen capture, overlays and session-install APIs. Kaspersky counted 162,275 new mobile banking-trojan installation packages in Q1 2026; attacks on Android users rose 56% in 2025 and new packages 271% to 255,090. — [TechRepublic](https://techrepublic.com/article/news-android-malware-stealing-pin-overlay-attack), [Fintech News SG](https://fintechnews.sg/136967/security/malicious-mobile-banking-software-proliferates/), [Dawn](https://www.dawn.com/news/1978843/WhatsApp:/send) (vendor statistics; methodology differs by vendor)
- [S] Malware is converging on the agent design: RatHat (Zimperium, Sep 2026) combines accessibility abuse with remote AI decision-making, and uses Accessibility to read the ADB pairing code off the screen and pair with the debug interface without user interaction; RemControl (Group-IB, seen since Jul 2026) captures a machine-readable map of every visible UI element. — [Security Affairs](https://securityaffairs.com/199317/malware/rathat-turns-android-accessibility-into-an-attack-weapon.html), [Malwarebytes](https://www.malwarebytes.com/blog/news/2026/09/new-android-malware-uses-ai-to-steal-bank-logins-and-pins), [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/banking-trojan-remote-control/)
- [S] Google's Advanced Protection Mode restricts which apps may request accessibility permissions. — [Security Affairs](https://securityaffairs.com/199317/malware/rathat-turns-android-accessibility-into-an-attack-weapon.html)
- [P via CSA] Co-installed malicious app as attacker: with only permissions an ordinary third-party app can request (overlay, accessibility; no root) an app can inject invisible instructions, spoof UIs, sniff typed credentials, intercept input broadcasts and race the screenshot file. — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mobile-agent-attack-surface-screen-injecti/)
- [P via The Hacker News] Notifications and messages as a zero-click push channel: any WhatsApp/Slack/SMS/Signal/Instagram/Messenger sender could inject Gemini on Android; consequences crossed into the physical world (Google Home windows, boiler, lights), video streaming via a Zoom app link, memory poisoning and scheduled persistence. — [The Hacker News](https://thehackernews.com/2026/06/whatsapp-slack-notifications-could.html)
- [P via The Hacker News] Voice/screen split is mobile-specific: the "muted" variant hides the real authorisation question in link text that TTS skips, so the spoken confirmation differs from the on-screen one. — [The Hacker News](https://thehackernews.com/2026/06/whatsapp-slack-notifications-could.html)
- [P] Measured mobile ASRs: 93% max on AndroidWorld (AEIA-MN, 2025, older); 40.4-66.9% across six agents on MobileWorldSafety (Aug 2026), with directed communication (messages, email) the most effective carrier. — [arXiv 2502.13053](https://arxiv.org/abs/2502.13053), [arXiv 2608.17659](https://arxiv.org/html/2608.17659v1)
- [P] Privileged system agents: Doubao's OS-level INJECT_EVENTS permission needs no app cooperation; per-step screenshots go to the cloud; bank balances were exposed on mirrored devices; bystanders' data in shared chats is processed without their knowledge; "No rule currently stops other manufacturers from granting similar permissions". — [Lawfare](https://www.lawfaremedia.org/article/china-s-agentic-ai-controversy)
- [P] Payment and banking apps reacted by blocking: banks "could not distinguish agent actions from user actions"; Alipay reportedly treated them as cheat scripts; ByteDance suspended banking/payment/gaming automation. — [Lawfare](https://www.lawfaremedia.org/article/china-s-agentic-ai-controversy), [Yicai Global](https://www2.yicaiglobal.com/news/wechat-some-chinese-banking-apps-reportedly-restrict-devices-with-bytedances-new-ai-voice-assistant)
- [P via CSA] Hardware/display specifics: rounded corners and camera cutouts create regions present in the framebuffer but invisible to the user. — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mobile-agent-attack-surface-screen-injecti/)
- [S] Planned platform mitigations on Android (May 2026): non-dismissable automation indicator, purchase confirmations, per-app access controls for Gemini. — [AndroidGuys](https://androidguys.com/news/google-details-security-and-privacy-framework-for-gemini-intelligence-on-android/)

### Inferences
- On a phone the attacker's cheapest entry is sending a message: no website visit, no install. Combined with MobileWorldSafety's finding that directed communication is the strongest carrier, inbound messaging/notification content is the top mobile threat vector.
- The mobile OS has no equivalent of the browser's origin model for agents to hook into (Chrome's Agent Origin Sets has no shipped Android per-app analogue yet beyond the announced per-app access controls), and the accessibility tree/screenshot gives weaker provenance than the DOM.
- Phone agents inherit a dual-use problem: the same capability set is how anti-fraud systems fingerprint trojans, so legitimate agents need attestable identity and a sanctioned channel, or they will be blocked by high-value apps.
- Small on-device or GUI-specialist models are weaker at recognising injections (near 20/20 perception-attack success including AutoGLM's lightweight variant), so the privacy benefit of on-device inference trades against robustness.
- SMS/notification OTPs are both readable by the agent and deliverable by the attacker, which makes OTP-based step-up authentication a weak confirmation mechanism for agent-initiated actions.

### Gaps
- No public security evaluation of iOS screen-operating agents was found.
- No measured ASR for shipped OEM system agents (Honor YOYO, Huawei, Samsung/Gemini screen automation, Doubao) with production safeguards.
- Deep-link/intent-based attacks against agents: only the Zoom app-link demo was found; no systematic study identified.
- Banking-trojan statistics are vendor-reported and were taken from press coverage, not the reports themselves.
- I found no documented case of real malware specifically targeting a deployed phone agent (as opposed to malware adopting agent-like techniques).
